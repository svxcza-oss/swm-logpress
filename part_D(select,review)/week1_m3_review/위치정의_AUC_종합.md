# 위치 정의와 AUC 판정 — 가설 ①②③ 종합

## 0. 판정식 조건

- 프리즈 문서에서 위치(§4)는 "로그 뭉치, 관측단위마다 달라짐"이라고만 정의되어 있다. 이를 구체화하지 않고 평가에 들어가면 AUC 신뢰도가 떨어진다 (결과에 맞춰 가설을 조작할 위험).
- 판정 기준: 결합신호(희귀도 + 위치) AUC ≥ 0.65.
- 가설은 **"원인 줄은 가운데 묻혀 있다"(lost-in-the-middle)** 이다. 그러나 "가운데"가 무엇인지 — 2억 줄 중 가운데인지, 시간 순서 중 가운데인지 — 를 정하지 않으면 성립하지 않는다.
- 즉 **위치 정의를 어떻게 하느냐에 따라 검증하는 가설 자체가 달라진다.** 관측 범위만 다를 뿐(전체 / 5분 / 1시간), 모두 "가운데를 본다"는 점은 같다.

> 본 문서의 수치는 계산을 도구에 맡겨 얻은 값이며, 판단은 직접 수행한다.

## 1. AUC 공식

AUC의 정의는 **"원인 하나, 평범 하나를 뽑았을 때 원인 위치가 더 높을 확률"** 이다. 계산은 모든 쌍을 세는 것.

| AUC | 의미 |
|---|---|
| 1.0 | 원인이 항상 이김 (원인 위치가 늘 큼) = 완벽 구별 |
| 0.5 | 반반 = 구별 못 함 |
| 0.334 | 원인이 34%만 이김 = 원인이 오히려 더 작은 값(앞쪽)에 있음 |

예시 (쌍 비교):

```
원인 0.9  vs  정상 0.2  → 원인 승
원인 0.1  vs  정상 0.7  → 원인 패
원인 0.3  vs  정상 0.2  → 원인 승
```

- 위치값의 크기: 0.9 = 창 뒤쪽, 0.1 = 창 앞쪽.
- "더 높을 확률" = "원인이 더 뒤에 있을 확률". 본 결과는 반대로 **원인이 앞쪽에 있음**을 뜻한다.

### 순위(rank) 공식 — Mann-Whitney U

$$\text{AUC} = \frac{R_{pos} - \dfrac{n_{pos}(n_{pos}+1)}{2}}{n_{pos} \times n_{neg}}$$

- $R_{pos}$ : 양성들의 순위 합 (양성·음성 모두 포함해 정렬한 뒤, 양성들의 순위만 합산)
- $n_{pos},\ n_{neg}$ : 양성·음성 개수 (전체 로그 기준)

**계산 과정 (예시 값)**

1. 양성·음성을 합쳐 작은 값부터 순위를 매긴다.

| 값 | 라벨 | 순위 |
|---|---|---|
| 0.2 | 음성 | 1 |
| 0.3 | 양성 | 2 |
| 0.5 | 양성 | 3 |
| 0.6 | 음성 | 4 |
| 0.7 | 음성 | 5 |
| 0.9 | 양성 | 6 |

2. 양성 순위만 더한다 → $R_{pos} = 2 + 3 + 6 = 11$
3. 공식에 대입:

$$U = 11 - \frac{3 \times 4}{2} = 11 - 6 = 5, \qquad \text{AUC} = \frac{5}{3 \times 3} = \frac{5}{9} = 0.556$$

> 실제로는 양성 14,819 × 음성 14,939 = 약 2억 2,138만 쌍을 비교한 것과 같으며, Mann-Whitney U로 정렬해 빠르게 계산한다. 동점은 평균 순위로 처리한다.

## 3. 가설 ① 파일 전역

| 항목 | 값 |
|---|---|
| 위치 단독 AUC | **0.5540** |
| 양성 평균 / 음성 평균 | 0.5539 / 0.5000 |
| 정의되는 행 | 29,758 / 29,758 (100%) |
| 같은 노드·1시간 창 내 위치 폭 (중앙값) | **0.000000** |

| | 분포 (0 → 1) | 평균 | 형태 |
|---|:---|:---:|---|
| **양성** | ▁▂▃▇▂▅▇▁▂ | 0.554 | 봉우리 두 개 (균등 ❌) |
| **음성** | ▅▅▅▅▅▅▅▅▅ | 0.500 | 골고루 (균등 ✅) |

### ①의 문제점

- **음성만 균등분포** → AUC가 양성 평균(0.554)을 그대로 읽는다.
- 로그 뭉치를 파일 전체 기준으로 0~1로 정의하면 **위치와 시간이 같아져 교란**이 발생한다.

```
파일 앞부분(0.1) = 2005년 11월 (초반)
파일 중간 (0.5) = 2006년 3월  (중반)
파일 뒷부분(0.9) = 2006년 6월  (후반)
```

- 위치 = 시각이 되어, 이 줄이 찍힌 **시기를 외우고** 결과가 오염된다. 데이터가 몰린 시기에 가장 큰 원인이 있었다고 학습하게 된다.
- **위치 폭 중앙값 0.000000의 의미**: 매칭하면 음성이 양성 옆(같은 노드·시간대)에 붙어 위치가 거의 같아진다 → AUC가 0.5로 붕괴한다.

### 왜 음성이 균등분포이면 AUC가 무의미한가

음성이 [0,1] 균등분포이면, 양성 하나가 값 $x$일 때 그것이 음성보다 클 확률은 **정확히 $x$** 이다.

> **시험 점수 비유:** 100명이 1~100점에 골고루 퍼져 있을 때(균등분포), 내가 70점이면 나보다 낮은 사람은 70명. 아무나 뽑아 비교했을 때 그 사람이 나보다 낮을 확률은 70%. 이것이 균등분포에서 항등함수가 되는 이유다.

$$P(X_{pos} > X_{neg} \mid X_{pos}=x) = x$$

이를 모든 양성에 대해 평균 내면:

$$\text{AUC} = E[X_{pos}] = \text{양성 위치의 평균}$$

**검증**

| | 값 |
|---|---|
| 양성 평균 | 0.553919 |
| 실제 AUC | 0.553967 |
| **차이** | **0.000048** |

→ 일치. **유의미한 결과로 쓸 수 없다.**

## 4. 가설 ② 관측단위 내부 (노드·템플릿·5분)

| 항목 | 값 |
|---|---|
| 위치 단독 AUC | **0.5000** |
| 양성 평균 / 음성 평균 | 0.5000 / 0.5000 |
| 정의되는 행 | 10,605 / 29,758 (**35.6%**) |
| 정의된 행의 구성 | 양성 10,274 / 음성 331 |

### 템플릿이 섞일 수 없는 구조

- 원인 템플릿: 1, 2, 4, 7, 8, 9
- 정상 템플릿: 나머지 719종
- **겹치는 것: 0개** → 템플릿만 보면 원인/정상을 무조건 구별 가능.

프리즈 §5 원문: 한 관측단위 안에는 무조건 같은 템플릿만 들어간다. 원래 이 정의는 위치 측정용이 아니라 **의사복제 방지(표본 세기)** 용이었으나, 위치 가설에 끌어온 것이다.

### 결과

- 관측단위를 묶을 때 템플릿이 같아야 하는데, **템플릿 자체가 원인/정상을 가르므로** 같은 템플릿으로 묶인 줄은 자동으로 한 종류만 남는다 → **섞일 수 없다.**
- 관측단위가 순수(원인만 or 정상만)하므로, 양쪽이 각자 0~1을 똑같이 채운다 → **양성 평균 0.5, 음성 평균 0.5, AUC 0.5** (완전한 균등, 모두 같다는 결론).
- 구조적으로 이렇게 될 수밖에 없다 (프리즈 §13의 alert 태그 문제 명시와 동일한 원리).

### ①②는 둘 다 탈락

**"신호가 약해서"가 아니라 구조적으로 잴 수 없는 상태다.**
- ① 음성만 균등 (자·지렛대 역할) → 양성 평균을 읽을 뿐, 매칭 시 소멸.
- ② 양성·음성 둘 다 균등 → 구별 자체가 불가.

## 5. 가설 ③ 컨텍스트 윈도우 내부 (노드 + 시계기준 1시간)

### 정의와 논리

- **위치**: 같은 노드의 시계기준 1시간 로그 뭉치 안에서 원인 줄이 앞·중간·뒤 어디쯤인지를 0~1로 잰 값.
- **같은 노드**: `^#\d+#$`를 제외한, 한 기계의 로그 뭉치. (Thunderbird는 수천 대 슈퍼컴퓨터 로그이며, 각 기계마다 노드로 구분된다.)
- **논리**: 실험 후반부(2단계=압축)에 LLM에 로그를 뭉치 단위로 넣으면 뭉치 안 가운데를 놓치는 lost-in-the-middle이 일어난다. 따라서 위치도 파일 전체가 아니라 **그 뭉치 안에서** 재는 것이 맞다 (후반부와 기준 통일).

### ③이 ①②를 둘 다 피하는 이유

- 뭉치에 정상 줄이 섞여 있어(②와 달리 순수하지 않음) 같은 뭉치 안에서 원인·정상이 다른 위치를 가질 수 있다 → 비교 가능.
- 뭉치 내부 위치는 시각과 분리돼(①과 달리) 매칭해도 죽지 않는다.
- 단, 뭉치를 양성 기준으로 중심정렬하면 원인이 항상 0.5가 되어 순환이 생기므로, **시계 기준 고정 격자(정각 경계)** 로 자른다.

### 결과

| 항목 | 값 |
|---|---|
| 위치 단독 AUC | **0.3338** |
| 양성 평균 / 음성 평균 | 0.3336 / 0.5012 |
| 정의되는 행 | 2,051,138 / 2,052,142 (**100.0%**) |
| 1줄 창 비율 (위치 미정의) | 6.9% |
| 방향 보정 AUC (1 − AUC) | **0.6662** |

> 양성 평균 0.33 → 원인 줄이 창 **앞쪽**에 몰림. 음성은 0.50(골고루).
> AUC가 0.5에서 벗어남 = ①②와 달리 **신호 있음** (양측검정이라 방향 무관).
> 완전한 값은 아니나, 신호의 의미가 존재한다.

## 6. ①②③ 비교

| 항목 | ① 파일 전역 | ② 관측단위 내부 | ③ 컨텍스트 윈도우 |
|---|---|---|---|
| 위치 단독 AUC | 0.5540 | 0.5000 | **0.3338** |
| 양성 평균 / 음성 평균 | 0.5539 / 0.5000 | 0.5000 / 0.5000 | 0.3336 / 0.5012 |
| 정의되는 행 | 100% | 35.6% | 100% |

> **①** 양성·음성 다르나(0.554) 음성이 눈금 → 무의미 + 매칭 시 소멸

## 7. 각 가설 계산 과정 (순위 공식 실측)

**가설 ①**
```
n_pos = 14,819    n_neg = 14,939    전체 29,758개 순위매김
[1] R_pos = 232,446,510
[2] 양성끼리 서열 14,819×14,820/2 = 109,808,790
[3] U = 232,446,510 − 109,808,790 = 122,637,720
[4] AUC = 122,637,720 / (14,819×14,939) = 122,637,720 / 221,381,041 = 0.5540
```

**가설 ②**
```
n_pos = 10,274    n_neg = 331    전체 10,605개 순위매김
[1] R_pos = 54,483,022
[2] 10,274×10,275/2 = 52,782,675
[3] U = 54,483,022 − 52,782,675 = 1,700,347
[4] AUC = 1,700,347 / (10,274×331) = 1,700,347 / 3,400,694 = 0.5000
```

**가설 ③**
```
n_pos = 14,724    n_neg = 2,036,414    전체 2,051,138개 순위매김
[1] R_pos = 10,116,215,157.5
[2] 14,724×14,725/2 = 108,405,450
[3] U = 10,116,215,157.5 − 108,405,450 = 10,007,809,707.5
[4] AUC = 10,007,809,707.5 / (14,724×2,036,414) = 10,007,809,707.5 / 29,984,159,736 = 0.3338
```

## 8. 가설 ③ 검증 — 템플릿 제거 vs 정상 로그 투입

"템플릿 하나 뺐다고 결과가 이렇게 달라지는가?"라는 의심에 대한 분해.

②와 ③의 실제 차이는 세 가지다.
1. 템플릿 조건 제거 (노드+템플릿+5분 → 노드+시간)
2. 시간창 5분 → 1시간
3. 데이터: 큐레이션 샘플 → 원본 로그 (정상 로그 200만 줄 추가)

| 조건 | 섞인 관측단위 | AUC |
|---|---|---|
| 원래 ② (템플릿+5분, 샘플) | 0개 | 0.5000 |
| 템플릿만 제거 (노드+5분, 샘플) | 31개 | 0.4867 |
| 템플릿 제거 + **원본 로그** = ③ | 5,944개 | **0.3338** |

- **템플릿 제거만으로는 거의 변하지 않는다** (0.500 → 0.487).
- **진짜 변화는 정상 로그 200만 줄이 들어와 창이 채워지고 섞이면서 발생**한다 (섞인 창 31 → 5,944개).
- 즉 ③이 정당화되는 이유는 **템플릿 제거 + 정상 로그**, 둘 다 필요하다.

### ①②에 정상 로그를 넣으면?

- **① → 0.578**: 위치 = 파일에서 몇 번째, 결국 시각을 외우는 것은 그대로. 매칭하면 다시 소멸.
- **② → 0.493**: 거의 안 변함. 템플릿 조건이 남아 있어 정상 로그를 넣어도 섞이지 않음.
- ②에서 템플릿까지 빼면 신호가 나오나, 그것은 이미 ② 가 아니라 ③ 계열이다.

## 9. 아티팩트 의심 — 진짜 신호인가, 장애 후 쏠림인가

정상 로그가 장애 후에 쏠려서 원인이 앞으로 밀린 것이라는 의심이 있다.

**검증 1 — 원인 줄 앞/뒤 정상 로그 비대칭**

| | 값 |
|---|---|
| 원인 앞 정상 로그 평균 | 33.6개 |
| 원인 뒤 정상 로그 평균 | 185.6개 |
| 뒤/앞 비율 | 5.5배 |

→ 원인 뒤에 정상 로그가 훨씬 많다. **장애 후 쏠림 정황이 존재한다.**

**검증 2 — 원인이 "맨 앞(0.0)"에 붙는가**

| | 값 |
|---|---|
| 원인 위치 = 0.0 (맨 앞) | 9.0% |
| 원인 위치 < 0.1 (앞 10%) | 24.6% |
| 원인 위치 중앙값 | 0.259 |

→ 원인의 9%만 맨 앞이고 나머지는 앞쪽에 "퍼져" 있다. **단순 "장애=시작점" 아티팩트로는 설명되지 않는다.**

**결론:** 신호의 존재는 확실하나, 진짜 위치 신호와 장애 후 쏠림이 **섞여 있다.** 정확히 가르려면 매칭(1:1 / 1:4)을 해야 한다. 매칭하면 쏠림이 양쪽에 동일하게 적용돼 상쇄되므로, **매칭 이후의 값이 확실한 진짜 값**이다. (현재 0.3338은 매칭 전 예비값.)

---

## 10. 세 신호의 역할 — 위치 / 희귀도 / 결합

세 AUC를 모두 계산하되 역할을 나눈다.

| 신호 | 역할 | 신뢰 |
|---|---|---|
| **위치 단독** | 신호 존재 여부 **판정** | ✅ 누수 없음 (노드+시간, 템플릿 무관) |
| **희귀도 단독** | 누수 정도 **확인 (참고)** | ❌ 템플릿=라벨, 정답 훔쳐봄 |
| **결합** | 압축기 실제 **성능 (보고)** | △ 위치 단독으로 검증 필요 |

- **Q. 희귀도를 없애는가?** — 없애는 것이 아니라 **따로 본다.** 희귀도 계산은 하되, GO 판단에서는 위치 단독 AUC로 판별한다(누수 이슈). 판정 기준에서 **격리**하는 것이지 삭제가 아니다.
- **Q. 신호 판정을 위치 단독으로 해도 되는가?** — 희귀도·결합·위치 중 **유일하게 위치만 누수가 없다.** 진짜 신호가 있는지 판정하려면 위치밖에 쓸 수 없다.
- **희귀도 단독**: 템플릿에서 나와 정답을 훔쳐보므로 높게 나와도 신호로 못 믿는다. "희귀도만 보면 0.99가 나오는데 이는 라벨을 본 것"임을 드러내는 **투명성용**이다. 희귀도는 무조건 정답지가 될 수밖에 없다.
- **결합**: 희귀도+위치. 압축기가 실제로 쓸 신호이나, 좋게 나와도 "위치 덕인지 희귀도(누수) 덕인지"를 위치 단독과 비교해 판단해야 한다.

> **누수(템플릿)와 아티팩트(장애 후 쏠림)는 다른 문제다.** 위치는 라벨 누수는 없지만 쏠림 아티팩트는 있을 수 있으며, 전자는 위치 단독 판정으로, 후자는 매칭으로 각각 처리한다.

## 11. 확정 (Week 2)

**위치 정의를 가설 ③ (컨텍스트 윈도우) 으로 확정한다.**

- **정의**: 위치 = 같은 노드 + 시계기준 1시간 정각격자 뭉치 안에서의 상대위치 (rank / (n−1), 0~1)
- **예비 결과**: 위치 단독 AUC 0.3338 (방향보정 0.6662) — 신호 존재. 단, 매칭(1:1/1:4) 이후 값이 최종.
- **1시간 근거**: 성능이 아니라 매칭(±1시간)과의 기준 통일 (p-해킹 회피).
- **알려진 한계** (기존 문서에 명시, 매칭으로 상쇄):
  1. 정각 경계 걸침 — 양성의 약 17%가 경계 ±5분에 위치, 사건이 두 창으로 분리될 수 있음.
  2. 장애 후 로그 쏠림 아티팩트 — 원인이 앞쪽에 몰리는 것이 부분적으로 쏠림에서 기인할 수 있음.
- **①② 대비 우위**: ① 매칭 시 0.5 붕괴 / ② 구조적 0.5 / ③ 유일하게 신호 존재.
- **최종 확정**: 프리즈 §4 개정 서명 시 (4인).
