# 킬스위치 프리즈 — 전체 흐름 정리

## 1. 킬스위치 프리즈는 무엇을 설명하는가

- 최종 목표는 **로그 압축기**다. 로그를 압축해도 원인 줄이 살아남게 하여 LLM이 근본 원인을 찾게 하는 것.
- 이것이 성립하려면 전제가 필요하다: **LLM이 원인 줄을 알아볼 수 있어야 한다.**
- 그 전제를 검증하는 질문: **원인 줄이 애초에 구별 가능한 특징을 가지고 있는가?**
  - 없으면 → LLM에게 줘도 소용없음 → 프로젝트 접기(NO-GO)
  - 있으면 → 다음 단계로

- **단계 순서**
  1. (킬스위치) 원인 줄에 구별 가능한 신호가 있나?
  2. (Tier-1) 압축해도 원인 줄이 살아남나?
  3. (Tier-2) 살아남은 원인 줄을 LLM이 실제로 근본 원인으로 짚어내나?

- 즉 킬스위치는 **원인 식별 가능성을 검증하는 관문(Week 3)**이다.

### 프리즈 문서의 목적

- 결과를 보기 전에 규칙을 다 정하고 **서명·커밋**한다.
- 그래야 결과를 보고 유리하게 기준을 바꾸는 **p-해킹을 방지**한다. (사전등록)

---

## 2. 킬스위치 문서는 무엇을 설명하는가

- **원인 줄을 어떻게 식별할 것인가**에 대한 가설을 세운다.
- 희귀도와 위치를 합쳐 **결합신호**를 찾는다고 가정한다. (결합신호 = 원인 줄 식별 신호)

### 판정의 형식 = 가설검정

> AUC를 재는 것 = Mann-Whitney U 검정 = H₀/H₁ 판정. 모두 같은 것.

```
[준비] 위치 정의(③) + 음성 매칭(§8) + 표본 확정
   ↓  이것이 모두 "공정한 H₀/H₁ 검정"을 위한 세팅
[검정] H₀: 위치 무관(AUC=0.5)  vs  H₁: 관계있음(AUC≠0.5)
   ↓
[판정] AUC 측정 + 순열검정으로 p값 → H₀ 기각되나?
   ↓
GO / NO-GO
```

- 양측검정이므로 **0.5만 벗어나면 된다** (방향 무관).

### GO 판정식

- 관측 단위 총수(양성+음성) 충분할 것.
- Thunderbird는 양성이 비교적 부족하므로 **최소 조건을 양성 60으로** 세움.
- 음성은 VAPI 제외 기준으로 다시 측정 예정.
- 판별력(정말 쓸 수 있는 데이터인가) 검증은 Week 3 예정.

> 나머지 설명은 위 결정들을 정당화하는 근거들이다.

## 3. §0 — 라벨 대 신호 (순환 방지)

- **순환**: 답을 문제에 적어놓아 구별의 의미가 없어지는 것.
- 채점 기준(정답지)을 alert 태그만으로 만들면, 위치를 구별에 쓸 수 없다. 그래서 희귀도·위치를 신호로 둔다.

**핵심 논리**

- alert 태그로 원인을 정함 → **위치를 안 보고 정한 것** → 좋음(순환 없음).
- 만약 위치로 원인을 정하면 → 순환 발생. 태그로 정하면 괜찮음.
- 정하고 나서 세어보니 **원인의 59%가 중간에 있음을 발견**.

**alert 태그가 쓰이는 곳 = 정답을 만들 때.** AUC 측정 때는 태그를 쓰지 않고, 위치로 원인/정상을 구별할 수 있는지를 잰다. (AUC에 넣는 점수가 위치 하나뿐이라는 뜻)

| 단계 | alert 태그 | 위치 | 희귀도 |
|---|---|---|---|
| 정답(라벨) 만들기 | ✅ 씀 | ❌ | ❌ |
| 위치 단독 AUC | (정답지로 이미 씀) | ✅ 넣음 | ❌ |
| 희귀도 단독 AUC | (정답지로 이미 씀) | ❌ | ✅ 넣음 |
| 결합 AUC | (정답지로 이미 씀) | ✅ | ✅ |

```
[정답지]  alert 태그로 "누가 원인" 확정  (위치 안 봄)
              ↓
[답안]    위치 점수로 원인 맞히기 시도    (태그 안 봄)
              ↓
[채점]    정답지 vs 위치 답안 = AUC
```

- alert 태그는 **정답지 그 자체**.
- 정답지(태그)와 답안(위치)을 서로 안 보고 따로 만들어 채점 = **순환 방지**.

> "59.2%가 중간" 문장의 의미: 정답지(태그)로 원인을 정할 때 위치를 안 봤고, 정한 뒤 세어보니 원인의 59%가 중간이더라는 **관측**이다. 위치로 정답을 만든 게 아니라, 정답을 만들고 위치를 관측한 것.

## 5. 표본 단위 & 제외 규칙

- **관측 단위 1개 = ROC 곡선 위의 점 1개.**
- 관측 단위 = (노드, 템플릿, 5분).

**템플릿이란**: 로그 문구에서 변하는 부분(숫자·ID)을 `<*>`로 지우고 뼈대만 남긴 것(Drain3 도구). 예: `node-042 disk sda1 I/O error` 등 3줄 → `node-<*> disk <*> I/O error` 1개.

**제외 규칙**
- **CHK_DSK**: 디스크 고장 경고 태그. 13줄뿐이고 전부 한 노드(tbird-admin1)에 몰려, 노드 교란 통제가 안 돼 제외.
- **템플릿 3(본문 없음)의 총 라인 77**: EXT_FS 33 · VAPI 30 · MPT 8 · CPU 5 · SCSI 1 = 77.

## 6. 의사복제 방어

- **표본 부풀림**: 한 사건이 로그 수백 줄로 찍혀 표본이 부풀려지는 현상.
- 그래서 줄 단위가 아니라 **관측 단위**로 측정한다. 측정 결과 원인 템플릿 6종.

**"그렇다면 사건도 6개로 단순화되는 것 아닌가?" — 아니다.**

- 템플릿(종류)은 6개가 맞지만, 사건이 6개는 아니다.
- 같은 CPU 에러라도 서버 A에서 3월에 한 번, 서버 B에서 5월에 한 번 → 각각 **독립 사건**.
- 그러니 사건은 6개가 아니라 수천 개. (감기는 병으로는 1종류지만 감기 걸린 사건은 수천만 건인 것과 같다.)

**독립성 근거 (데이터 확인)**
- **3,077개 노드에 분산** — 같은 에러가 3천 개 다른 기계에서 각각 발생 (한 기계 쏠림 아님).
- **210개 날짜에 분산** — 여러 날에 걸쳐 각각 발생 (하루 쏠림 아님).
- **상위 15개 노드가 37%뿐** — 특정 서버 쏠림 없이 골고루 분산.

## 7. 양성 정의

- **양성 = alert 태그가 붙어 있고 본문에 error류 단어가 없는 줄.** 여기에 §5 제외 규칙을 적용한 것이 분석 모집단.
- **level·alert_tag는 신호로 사용 금지**: 정의의 구성요소이므로 특징에 넣으면 라벨 누수. alert_tag는 정답 계산 전용으로 격리.

## 8. 음성 매칭 규칙

- AUC는 원인(양성) vs 평범한 줄(음성) 비교다. 음성을 아무렇게나 뽑으면 비교가 사기가 된다. 그것을 막는 것이 §8.

**§8과 가설 ③은 다른 것**

| | §8 (매칭) | 가설 ③ (위치 정의) |
|---|---|---|
| 무슨 얘기 | 음성을 어떻게 뽑나 | 위치를 어떻게 재나 |
| 정하는 것 | 양성과 짝지을 음성 선택 | 위치 계산 범위 |
| 언제 나옴 | 프리즈 원래부터 있음 | 나중에 ①② 실패 후 D가 만듦 |

**왜 음성 뽑는 방법만 정하는가**

- **양성은 이미 정해져 있다** — alert 태그가 붙은 줄. 임의로 붙인 게 아니고, 존재하는 양성을 전부 쓰므로 고를 필요가 없다.
- **음성은 열린 선택지** — 평범한 줄이 200만 개나 되어, 그중 무엇을 고르느냐가 결과를 좌우한다.

```
[나쁜 음성 — 아무 데서나]
양성: 장애 시간대(03시), 특정 노드에 몰림
음성: 아무 시간·아무 노드 (예: 낮 12시, 다른 노드)
→ 시간·노드가 완전히 다름
→ "03시면 양성, 12시면 음성" 시간만 보고 맞힘
→ 위치·희귀도 실력이 아니라 교란으로 맞힌 것

[좋은 음성 — §8 매칭]
양성: 03시, 노드 A
음성: 같은 03시 근처, 같은 노드 A
→ 시간·노드가 같음 → 그것으론 구별 못 함
→ 오직 위치·희귀도로만 구별 → 진짜 실력 시험
```

- 마지막 임계값 근거는 검정력 분석에서 설명.

# 검정력 분석은 무엇을 말하는가

## 왜 AUC가 0.65를 만족해야 하나

- AUC 0.65 = rank-biserial r=0.30 = **Cohen 중간효과 하한**과 일치(등식). 임의 기준이 아니라 "육안으로 알아볼 수 있는 중간 크기"라는 표준 효과크기 기준.

## 1:1 / 1:4 매칭 비율

- **1:1, 1:4 = 양성:음성 매칭 비율.**

**왜 둘 다 하나 (강건성)**
- 1:1에서만 신호 있음 → "균형 맞춰 억지로 된 거 아니냐" 의심.
- 1:4에서도 신호 있음 → "불균형에서도 되네, 진짜네."
- 검정력 분석의 표본수 역산: 1:1에서 필요한 양성 57개, **1:4에서 37개**(음성을 늘리면 검정력↑).
- "그 비율이라 된 거 아니냐"는 예상 반박을 미리 막는 방어 논리.
- 1:4를 뽑을 때 첫 번째를 1:1용으로 써서 두 실험을 일관되게 맞춘다.

## 표본 최소 조건 (계산된 값)

- 양성 ≥ 60
- 양성 + 음성 ≥ 300

## 결합신호 유의성 검정 — 순열검정

```
1. 정답(원인/정상 라벨)을 무작위로 섞음
   → 위치와 정답의 관계를 일부러 끊음 = "신호 없는 가짜 상황"(H₀)
2. 그 가짜 상황에서 AUC 측정
3. 5,000번 반복 → "신호 없을 때 AUC 분포"를 만듦
```

- 5,000회 = 우연의 분포를 정밀하게 그리기 위한 반복 횟수(관행값). **숫자 자체보다, 결과를 보기 전에 미리 정해 넣는다는 점이 더 중요하다.**

```
가짜 분포(신호 없을 때): 대부분 0.48~0.52에 몰림
실제 AUC: 예) 0.33
→ 실제값이 가짜 분포에서 얼마나 극단적인가?
```

- **p값** = 신호가 없는데도 실제값만큼 극단적인 AUC가 나올 확률.
  - 5,000번 중 실제값만큼 극단적인 게 10번 → p = 10/5000 = 0.002.
- **p < 0.05** = 우연으로 이게 나올 확률이 5% 미만 → 우연 아님 → 진짜 신호 → H₀ 기각.

> AUC ≥ 0.65(크기)와 순열검정 p < 0.05(우연 아님), 두 기준 모두 신호가 유의미함을 보이려는 것.

# 위치 정의

## AUC 공식

- AUC = 원인 하나와 평범한 줄 하나를 뽑아, **원인이 더 높은 위치일 확률.**
- Mann-Whitney U 공식 = 이것을 일일이 세지 않고 **순위 합으로 빠르게** 구하는 공식.

## 가설 ① 파일 전역

- **가정**: 파일 전역에서 로그 뭉치의 위치를 0~1로 잡는다.
- **문제**: 파일 전역을 위치로 잡으면 **위치 = 시간**이 된다.
  - 왜: 위치를 전역으로 잡으면, 0~1 값이 곧 전체 시간 흐름과 같아지기 때문.
- **양성 평균·음성 평균이 거의 같아지는 이유**:
  - 음성(정상 로그)은 파일 전체에 골고루 분포 → **균등분포**가 됨.
  - 양성도 Thunderbird 원본 데이터 분포를 그대로 따라감.
  - 음성이 균등분포이면 AUC가 양성 평균을 그대로 읽어버려 무의미. (매칭하면 0.5로 붕괴)

## 가설 ② 관측 단위 내부

- **가정**: 관측 단위 내부에서 위치를 측정.
- **결과**: 이것도 균등분포가 됨 (양성·음성 둘 다 0.5).
- **왜 (핵심)**: 관측 단위 = (노드, **템플릿**, 5분)인데, **템플릿이 양성 또는 음성을 완전히 가른다**(양성 템플릿 ∩ 음성 템플릿 = 0).
  - 그래서 같은 템플릿으로 묶인 관측 단위는 **자동으로 전부 양성이거나 전부 음성**이 된다(순수).
  - 순수한 관측 단위에서는 원인이든 정상이든 각자 0~1을 똑같이 채우므로, 위치 평균이 모두 0.5 → AUC 0.5.
  - 즉 "위치 신호"가 아니라 "템플릿"을 따라갈 수밖에 없다.

## 가설 ③ 컨텍스트 윈도우 (채택)

- **가정**: 위치를 (노드 + 시계기준 1시간) 로그 뭉치 안에서 측정. **격자 기반.**
- **정각으로 자른 것과 격자의 차이**:
  - **격자 = 시계 기준 고정 경계(정각)로 자른 것** 자체를 말한다. 둘은 같은 것.
  - 반대 개념은 "양성 중심 정렬"인데, 양성을 기준으로 자르면 양성이 항상 창의 특정 위치(맨 앞/가운데)에 고정되어 **순환**이 생긴다.
  - 그래서 양성과 무관한 **정각 격자**로 잘라야 순환이 없다.
- **같은 노드 = 한 기계 단위** → 위치를 **기계 단위 뭉치 안에서** 재는 것.

**①②와의 차이**
- 원본 로그(정상 줄)를 넣음 → ①②와 차이.
- 템플릿 조건을 제거함 → ②와 차이.

**왜 ①②에 원본 로그를 넣고 템플릿을 제거해도 결과가 거의 안 변하나**
- **① 에 원본 로그를 넣어도**: ①의 근본 문제는 "위치 = 시간"이라는 성질이다. 데이터를 더 넣어도 이 성질은 안 바뀌고, 매칭하면 여전히 0.5로 붕괴한다. (시각 교란이 근본 원인)
- **② 에서 템플릿만 제거해도**: 큐레이션 샘플에는 정상 로그가 거의 없어 창이 안 채워지므로 여전히 섞이지 않는다. (정상 로그 부재가 근본 원인)
- 즉 ③의 신호는 **템플릿 제거 하나만으로 나온 것이 아니라, "템플릿 제거 + 정상 로그 투입" 둘이 동시에 필요**하다. ①은 그 둘을 해도 시각 교란 때문에 안 된다.
