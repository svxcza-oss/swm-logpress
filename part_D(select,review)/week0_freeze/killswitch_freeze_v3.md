# LogPress · Kill-switch 프리즈 (관문 ①, M1 · 3주차)

**데이터 접근 전 확정·서명·커밋.** 결과를 본 뒤 임계값·규칙 변경 시 사전등록 효력 소멸.

이 문서의 존재 이유: 실험 전 측정 기준을 미리 설계하여, 운 좋게 나온 결과와 구별하고 결과의 논리를 방어하기 위함.

**이 문서를 읽는 법** — 대부분의 내용은 "구현할 코드"가 아니라 "그 코드가 왜 정당한지에 대한 근거"다. 실제로 구현하는 것은 아래 0장의 5가지뿐이며, 나머지 장(3·6·8·9 등)은 그 5가지가 결과 조작이 아님을 증명하는 사전 설계다.

> **📎 분리 문서 안내**
> AUC·ROC의 정의, Mann-Whitney U 동치, `r = 2A−1` 환산, Cohen 효과크기, Hanley-McNeil 표본수 역산은 **`_검정력_분석_case_count.md`** 로 이관했다. 본 문서는 그 결과값만 인용하며 유도 과정을 중복 설명하지 않는다. 해당 내용은 검정력 분석 **§0(개념 정리)** 과 **§1(근거)** 를 참조할 것.

>
> **심사 대응 문장:** *"VAPI 30줄은 제외했습니다. 다만 태그가 VAPI라서가 아니라 본문이 비어 있어서입니다. 본문이 빈 76줄을 태그와 무관하게 모두 제외했고, VAPI 30줄은 그중 일부입니다."*

### 실제 구현 (코드로 만드는 것 — 5가지)

| # | | 구현 내용 |
|---|---|---|
| 1 | 희귀도 계산 | 템플릿이 전체 로그에서 몇 번 나왔는지 세기 |
| 2 | 위치 계산 | 줄이 로그 뭉치에서 어디쯤(0~1)인지 |
| 3 | 음성 매칭 | 같은 노드·±1시간에서 평범한 줄 뽑기 |

위 5가지가 왜 정당한지 방어하는 근거다. 순환 방지(3장), 의사복제 방어(6장), 교란 통제(8장), 재현성(9장)은 모두 "결과를 조작하지 않았음"을 사전에 못 박는 설계다.

**최종 판정** — AUC ≥ 0.65 & 순열검정 p < 0.05 → **GO**, 아니면 **NO-GO**(신호 재설계 또는 주제 리셋).

## 1. 가설

원인 줄을 찾는 단서 두 개를 합쳐 점수 하나로 만든 것이 **결합 신호**(희귀도 + 위치). (4장 참고)

- **희귀도(rarity)**: 이 로그 문구가 전체에서 몇 번 나왔나 카운팅. 드물수록 원인일 가능성이 높다는 가설.
- **위치(position)**: 로그 뭉치를 0~1로 놓고 이 줄이 어디쯤인지. 맨 앞 0, 한가운데 0.5, 맨 끝 1.

**둘 다 쓰는 이유:** 희귀도는 템플릿마다 값이 하나로 정해진다(같은 템플릿이면 어디서 나오든 희귀도 동일). 양성 템플릿이 6종이고 그중 **상위 4종이 99.8%**를 차지하므로, 희귀도의 **실질 분해능은 약 4**다. 관측 단위는 6,637개인데 구별되는 값은 사실상 4개. 그래서 위치를 붙여 촘촘하게 만든다.

| | 가설 내용 |
|---|---|
| **H₀** (귀무) | 결합 신호가 원인 줄을 평범한 줄과 구분하지 못한다 (AUC = 0.5, 동전던지기). |
| **H₁** (대립) | 결합 신호가 원인 줄을 평범한 줄과 다르게 평가한다 (AUC ≠ 0.5). ← 우리가 주장할 것 |

> **검정 방향: 양측(two-sided), α = 0.05.** 표본수 근거(`n_pos` 57·37)가 `z₁₋α/₂ = 1.96`, 즉 양측으로 산출되었으므로 검정도 양측으로 통일한다. 방향 선택의 자의성은 6·9장의 사전등록(규칙 선커밋)으로 차단한다.

> **AUC 정의·`0.65`의 근거** → **검정력 분석 §0.2, §1-a** 참조.
> (요지만: AUC = 양성 하나와 음성 하나를 무작위로 집었을 때 양성 점수가 더 높을 확률. 0.65 → `r_rb = 0.30` = Cohen 중간 효과 하한과 **등식**으로 일치.)

## 3. 라벨 vs 신호 (순환 방지)

**순환이란?** 시험 문제를 내면서 답을 문제에 적어놓는 것. 정답을 "위치"로 정해놓고 "위치"로 맞히면, 당연히 맞지만 의미가 없다(답 보고 답 쓰기).

| 구분 | 사용 축 | 위치 포함? |
|---|---|---|
| 채점 기준 (정답 라벨) | alert 태그만 | ❌ 제외 |
| 정답을 맞추는 신호 | 희귀도 + 위치 | ✅ 포함 |

**alert 태그란:** 로그 줄 맨 앞의 이상 표시. `-`이면 정상, `PBS_CON`·`SCSI`·`CPU` 등이면 이상. Thunderbird 제작자가 내용을 보고 미리 붙인 것이라 위치와 무관하다.

```
이전 판(순환):
  정답 정의: "중간(0.25~0.75)에 있는 줄 = 원인"
  신호:      "중간에 있으면 원인일 것"
  → 위치로 정하고 위치로 맞힘 = 무의미. (b) 조항 삭제.

현재(순환 차단):
  정답 정의: "alert 태그 붙은 줄 = 원인" (위치 상관없음)
  신호:      "중간에 있으면 원인일 것" (위치 사용)
  → 정답은 위치를 모른 채 정해졌고, 신호가 위치로 맞힘
```

**"59.2% 중간 집중"이 왜 라벨이 아니라 관측 결과인가**
태그로 하드케이스를 정한 뒤(위치 안 봄), 세어보니 그것들의 59.2%가 중간에 있더라는 것. "중간에 있어서 하드케이스로 정한" 게 아니라 "태그로 정했더니 알고 보니 59.2%가 중간이더라"는 관측이다. 정답을 위치로 정했다는 근거가 아니라, **위치 신호가 통할 것이라는 유리한 정황**일 뿐이다.

**데이터 검증:** `is_anomaly`/`is_hardcase`가 `alert_tag`로 완전 결정되며, `position_ratio`는 라벨 규칙에 미포함(예외 0건).

> ⚠️ 위치는 순환에서 차단했으나, **희귀도 쪽에 별도의 결합 문제**가 남아 있다. §13-1 참조.

## 4. 신호 정의

| 신호 | 정의 | 특성 |
|---|---|---|
| **희귀도** | 템플릿이 전체 로그에서 몇 번 나왔는가. 드물수록 높은 점수. 200만 번 나온 흔한 문구는 낮고, 5번 나온 문구는 높음. | 템플릿당 1개 값 → **실질 분해능 약 4** |
| **위치** | 로그 뭉치 0~1 기준 상대 위치 (앞 0, 중앙 0.5, 끝 1). | 관측 단위(버스트)마다 달라짐 |

**결합 이유:** 희귀도는 같은 템플릿이면 값이 동일하다. 정본 6종 중 상위 4종이 99.8%를 차지하므로 사실상 4가지 값만 나온다. 위치는 같은 템플릿이라도 관측 단위(버스트)마다 값이 달라 촘촘함을 확보한다. 그래서 둘을 결합해 검정한다.

**잔여 리스크:** 위치 신호는 "중간=원인" 가정이 데이터 의존적. 원인이 로그 꼬리에 있는 롱테일 케이스엔 약할 수 있음. 실측 AUC가 낮으면 NO-GO 대응(11장)으로 이행.

### 4.1 결합 수식 (v3_8 확정)

AUC는 단일 점수로 순위를 매기므로 두 신호를 **하나의 점수로 합치는 규칙**이 필요하다. 이 규칙이 사전에 고정되지 않으면 "가중치를 여러 개 시도해 AUC가 가장 높은 조합을 채택"할 여지가 생긴다(p-해킹). 따라서 아래를 결과 확인 전에 확정한다.

**채택: 로지스틱 회귀.** 고정 가중치(예: 0.5:0.5)는 두 신호의 상대적 중요도를 정할 근거가 없어 그 자체가 자의적이다. 회귀는 계수를 데이터에서 추정하므로 "왜 그 비율인가"에 답할 수 있다.

| # | 조항 | 내용 |
|---|---|---|
| ① | **입력 특징** | `[표준화 희귀도, 위치]` **두 개만.** `level`·`alert_tag`·`template_id`는 절대 투입 금지(정답 누수, §6) |
| ② | **분할 단위** | **관측 단위(버스트) 기준** `GroupShuffleSplit`, `groups = burst_5m`. 라인 단위 분할은 같은 관측 단위(버스트)가 train/test에 걸쳐 누수 |
| ③ | **분할 비율·시드** | train 70 / test 30, seed는 `seeds.yaml`의 `logreg_split` |
| ④ | **표준화 fit 위치** | 평균·표준편차는 **train에서만 fit**, test에는 transform만. 전체로 표준화하면 누수 |

**보고 대상은 test set에서 산출한 AUC**이며, train AUC는 참고로만 병기한다.

### 4.2 3신호 병기 규칙 (필수)

결합 AUC 하나만 보고하는 것을 **금지**한다. 아래 세 값을 **항상 함께** 산출·보고한다.

| 신호 | 라벨 누수 위험 | 해석상 역할 |
|---|---|---|
| 희귀도 단독 AUC | **높음** — 템플릿이 곧 태그(§13-1) | 참고용. 높게 나와도 신호의 성취로 해석하지 않는다 |
| **위치 단독 AUC** | **없음** — 위치는 템플릿·태그와 무관 | **누수 없는 유일한 지표.** 실질적 핵심 관찰값 |
| 결합 AUC | 희귀도로부터 상속 | **주 판정값** (§2 조건 ②) |

**해석 규율 (사전 확정):**

> **주 판정은 결합 AUC로 한다.** 단 **위치 단독 AUC가 0.5 근처(CI 하한이 0.5를 넘지 못함)이면**, 결합 결과는 사실상 희귀도가 주도한 것이며 희귀도는 템플릿-라벨 결합 문제를 안고 있으므로, **"신호가 원인을 판별했다"고 주장하지 않고 그 사실을 결과에 명시**한다.

세 AUC 각각에 부트스트랩 95% CI를 붙이고, **세 검정에 BH-FDR을 적용**한다. 어느 것을 주 판정으로 삼을지는 위와 같이 사전에 고정되어 있으므로, 측정 후 "가장 잘 나온 값"으로 바꾸지 않는다.

**희귀도 단독 사용 금지:** rarity 단독 AUC는 분해능 한계와 템플릿-라벨 결합 문제(§13-1)를 명시해 **보조로만** 보고한다.

## 5. 표본 단위 & 제외 규칙

**(노드, 템플릿, 5분 시간창) 하나 = 관측 단위 1개(=버스트 1개 = ROC 곡선 위의 점 1개).** 같은 노드에서 같은 템플릿이 5분 안에 연달아 나오면 1개, 5분 이상 잠잠했다 재발하면 새로 1개. 셋 중 하나라도 다르면 별개 표본.

> **버스트 = (노드·템플릿·5분) = 관측 단위** — 셋은 같은 것의 다른 이름이다. "버스트"는 통칭("같은 에러가 몰린 덩어리"), "(노드·템플릿·5분)"은 그것의 정확한 정의, **"관측 단위"는 검정력 분석 문서의 표기**다.

**템플릿이란:** 로그 문구에서 변하는 부분(숫자·ID)을 `<*>`로 지우고 뼈대만 남긴 것(Drain3 도구 사용). 예: `node-042 disk sda1 I/O error` 등 3줄 → `node-<*> disk <*> I/O error` 1개.

| 기준 | 없으면 생기는 문제 |
|---|---|
| 노드 | 다른 서버 일을 같은 사건으로 착각 |

| 5분 | 어제 일과 오늘 일을 같은 사건으로 셈 |

## 6. 의사복제 방어

**의사복제** = 가짜로 표본이 많아 보이는 현상. 디스크 1개 고장에 로그 500줄이 찍히면, 줄로 세면 500개지만 실제 사건은 1개. 이를 막기 위해 줄 단위(14,819)가 아니라 **관측 단위(버스트, 6,637)**로 센다.

## 7. 양성 정의

**양성 = alert 태그가 붙어 있고 본문에 error류 단어가 없는 줄.** 여기에 §5의 제외 규칙을 적용한 것이 분석 모집단이다.

### 정의에 관한 주석

- **non-ERROR 조건 이유:** 본문에 error가 있는 줄은 기존 레벨 필터가 이미 잡는다. 우리 대상은 필터가 놓치는 **숨은 원인**.
- **태그를 사유로 삼은 제외는 하지 않는다.** 특정 태그(예: VAPI)가 전체 로그에서 흔하다는 사실은 그 태그의 **하드케이스 잔여분**을 제외할 근거가 되지 못한다. 잔여분은 정의상 레벨 필터가 놓친 줄이기 때문이다. 제외는 §5의 3항목(노드 식별 가능성 · 본문 존재)에 한정하며, 이는 **태그와 무관한 구조적 기준**이다.
  - 결과적으로 VAPI 30줄은 제외되지만, 그 사유는 태그가 아니라 **로그 메시지가 없다는 점**이다. 같은 사유로 EXT_FS 33 · MPT 8 · CPU 5 · SCSI 1도 함께 제외된다.
  - 반대로 **본문이 있는 VAPI 하드케이스가 있었다면 그것은 분석에 포함**되었을 것이다. 제외 여부는 태그가 아니라 구조적 조건이 결정한다.
- **`level`·`alert_tag`는 신호로 사용 금지.** 정의의 구성요소이므로 특징에 넣으면 라벨 누수가 된다. `alert_tag`는 정답 계산 전용으로 격리한다.

## 8. 음성 & 매칭 규칙

**왜 재추출하나:** 현행 비교군은 무작위 균등 추출이라 양성과 조건이 안 맞는다(position 0~1 균등, 시간 8개월 전 구간, 노드 3,876개로 불일치). 조건이 다르면 교란이 생겨 공정한 비교가 안 된다.

### 핵심 개념: 교란 & 교란 통제

```
교란 = 진짜 원인이 아닌데 결과에 영향 주는 것
  양성은 장애 시간대·특정 노드에 몰림.
  음성을 아무 데서나 뽑으면
  → "이 줄 03:22(장애 시각)네 → 양성!" 처럼 시간대만 보고 맞힘.
    AUC가 높아도 "신호가 좋아서(우리 실력)"인지
    "시간·노드가 달라서(교란)"인지 구별 불가.

교란 통제 = 시간·노드를 양쪽 똑같이 맞춰 상쇄.
  → 조건이 같으니 희귀도·위치로만 구별하게 됨 = 진짜 시험.
```

| 항목 | 처리 & 이유 |
|---|---|
| **맞출 것** | 같은 노드, ±1시간 이내 → 시간·노드 교란을 양쪽에서 상쇄 |
| **반대로 둘 것** | 음성은 alert 태그 `-`인 평범한 줄 → 조건은 같고 정답만 반대 |
| **건드리지 말 것** | position 매칭 금지 — 위치는 측정 대상. 양쪽 위치까지 같게 맞추면 위치로 구별할 게 없어져 신호가 죽는다 |
| **세는 단위** | 양성과 동일 (노드, 템플릿, 5분) = 관측 단위 |
| **비율** | 1:4로 뽑되 첫 번째가 1:1용. 따로 뽑으면 두 집합이 달라져 비교 불성립 |
| **음성 내 ERROR** | non-ERROR(INFO)로 한정 (현행 파일에 1,896개 혼입) |

### 후보 모으기 vs 후보 선택 — 2단계

```
1단계 (후보 모으기): "같은 노드 + ±1시간 + 평범한 줄"을 다 긁어모음
  → 후보 수십~수백 개 (평균 524, 중앙값 26)

2단계 (후보 선택): 그중 무작위로 1개(1:1) 또는 4개(1:4)
  → "가장 가까운 것"은 안 씀: 양성 직전·직후 줄이면
     같은 장애에 오염됐을 수 있음(정상 아닐 수도).
     교란 통제는 창 자체가 보장하므로 창 안에서는 무작위가 적절.
```

### 시간 범위 = ±1시간 (실측 근거)

| 범위 | 성공 | 실패 |
|---|---|---|
| 같은 5분 | 14,478 (96.9%) | 461 |
| ±30분 | 14,846 (99.4%) | 93 |
| **±1시간 (채택)** | **14,869 (99.5%)** | **70** |
| ±6시간+ | 14,939 (100%) | 0 |

> ⚠️ 위 수치는 **제외 전 14,939줄 기준**이다. 음성 재추출 시 정본 14,819줄 기준으로 재집계하고, 그 결과를 `negatives_matched.csv`와 함께 기록한다.

- **같은 5분 탈락:** 실패 461개가 "정상 로그 없이 갑자기 튄" 케이스라 오히려 가장 원인다울 수 있음.
- **±6시간+ 탈락:** 결과는 같은데 교란 통제만 느슨해짐. → ±1시간이 균형점.

### 매칭 실패 = 제외 금지 (선택 편향 방지), 2단계 폴백

**선택 편향** = 표본 고르는 방식 때문에 결과가 왜곡되는 것. 실패분은 "주변에 정상 로그가 없다 갑자기 튄" 케이스로 가장 원인다울 수 있어, 버리면 결과가 왜곡된다.

1. ±1시간 · 같은 노드 매칭
2. 실패 시 → 같은 노드 전체 기간으로 시간 제약만 완화 (노드는 유지)
3. 그래도 실패 → 제외하지 말고 민감도 분석에서 별도 집계·보고

**레벨필터 ERROR를 음성으로 안 쓰는 이유:** "숨은 원인 vs 뻔한 에러"를 묻게 되어 킬스위치 질문과 어긋나고, rarity가 자동으로 갈려 AUC가 부풀려짐. 서술적 근거로만 사용.

## 9. 검정 & 재현성

| 용도 | seed | 반복 | 산출물 |
|---|---|---|---|
| 음성 매칭 추출 | `seed_negative = 42` | — | `negatives_matched.csv` |
| 순열검정 | `seed_perm = 7` | **5,000회 고정** | `perm_null_dist.npy` |

### 순열검정이란

```
"이 정도 점수가 우연히 나올 수 있나?"를 실험으로 확인.
  1. 정답 라벨을 무작위로 섞음 (신호와 정답의 관계를 끊음)
  2. 그 상태로 AUC 계산
  3. 5,000번 반복 → "우연 점수" 5,000개 (귀무분포)
  4. 진짜 AUC가 이 분포에서 얼마나 극단적인지 양측으로 판정
     p < 0.05 = 우연히 이 점수가 나올 확률이 5% 미만
```

### 왜 하필 5,000회인가 — 세 가지 요건의 교집합

순열검정의 p값은 **유한 반복으로 추정한 값**이므로 자체 오차(몬테카를로 오차)를 갖는다. 반복수 `B`를 정하는 것은 그 오차를 어디까지 허용하느냐의 문제다.

**요건 ① — p = 0.05 부근에서 판정이 흔들리지 않을 것**

`p ≈ 0.05`에서 몬테카를로 표준오차는 `SE = √(p(1−p)/B)`이다.

| B | SE | 95% 신뢰구간 | p=0.05가 놓이는 범위 |
|---|---|---|---|
| 1,000 | 0.0069 | ±0.0135 | [0.037, 0.064] ← **0.05와 0.06 구분 불가** |
| 2,000 | 0.0049 | ±0.0096 | [0.040, 0.060] |
| **5,000** | **0.0031** | **±0.0060** | **[0.044, 0.056]** ✅ |
| 10,000 | 0.0022 | ±0.0043 | [0.046, 0.054] |

**0.05와 0.06의 차이(0.01)가 SE의 몇 배인가**로 보면 — B=1,000에서 1.4배(구분 불가), **B=5,000에서 3.1배**(안정적 구분), B=10,000에서 4.4배. 즉 **5,000에서 판정 안정성이 확보**되고, 그 이상은 비용 대비 이득이 급감한다.

**요건 ② — 최소 표현 가능 p값이 판정 임계값보다 충분히 작을 것**

순열검정의 p값은 `(귀무분포 중 실제 AUC 이상인 개수 + 1) / (B + 1)`이므로, 아무리 강한 신호라도 **`1/(B+1)` 미만으로는 내려갈 수 없다.**

| B | 최소 표현 가능 p |
|---|---|
| 1,000 | 0.0010 |
| **5,000** | **0.0002** |
| 10,000 | 0.0001 |

B=5,000이면 최소 p = 0.0002로, 판정선 0.05보다 **250배 아래**까지 표현된다. 다중비교 보정 후 기준이 조여져도 해상도가 남는다.

**요건 ③ — 재현 가능한 시간 안에 끝날 것**
B를 10,000으로 올리면 계산 시간이 2배가 되지만 신뢰구간은 ±0.006 → ±0.0043으로만 줄어든다. 판정 결론이 바뀌지 않는 개선에 비용을 두 배 쓰는 셈이다.

> **결론:** 5,000은 "관례"가 아니라 **① 판정 안정성 확보 · ② 충분한 p 해상도 · ③ 합리적 계산 비용**이 동시에 만족되는 최소 지점이다.
> **다만 가장 중요한 것은 숫자 자체가 아니라 "미리 정하고 결과를 본 뒤 바꾸지 않는 것"이다.** p값이 애매하다고 반복을 늘리는 것은 optional stopping = p-해킹이다.

### p-해킹 / optional stopping 방지

- **p-해킹:** 여러 방법으로 돌려보다 유의한 것만 보고. **optional stopping:** p값이 애매하면 반복·표본을 늘려 재시도. 둘 다 "우연히 잘 나온 것"을 진짜처럼 만든다.
- **방지책:** 순열 5,000회 고정, seed 고정, **검정 방향(양측) 사전 확정**, **제외 규칙 사전 확정(§5)**, 규칙 먼저 커밋. 반복·seed·방향·제외 기준은 결과를 보고 바꾸지 않는다.
- **인덱스 파일이 최종 증거** — seed만으론 라이브러리 버전 변화 시 재현이 깨질 수 있음. 추출된 `line_id` 목록·귀무분포를 파일로 남긴다.
- `requirements.lock`에 numpy/pandas/scipy 버전 고정 후 함께 커밋. **1회 실행 원칙**(재실행 시 사유·시각·변경점 기록, 이전 결과 보존).
- **현재 AUC 미측정(깨끗함).** 매칭 규칙 확정·커밋 → 음성 재추출 → AUC 측정 순서 준수.

### ⚠️ 13-1. 템플릿 ≈ alert 태그 ≈ 라벨 (희귀도 결합 문제)

§6의 템플릿 분포표에서 드러나듯 **각 템플릿에 alert 태그가 하나씩만 대응**한다(t8=PBS_CON, t7=MPT, t1=CPU, t2=SCSI, t9=PBS_BFD, t4=NMI). 그런데 **alert 태그는 곧 정답 라벨**(§3)이다.

따라서 희귀도는 템플릿에서 파생되므로, "이 줄이 드무냐"가 아니라 사실상 **"이 템플릿이 양성 태그의 것이냐"**를 인코딩할 수 있다. 실측으로 **템플릿 ID만으로 얻는 AUC가 1.0**에 달한다.

> **참고:** 제외 전에는 본문 없는 템플릿(t3)만이 여러 태그가 섞인 유일한 템플릿이었고, 그때의 템플릿-단독 AUC는 0.99999였다. 즉 **제외 여부와 무관하게 이 문제는 이미 존재**하며, t3 76줄로는 방어되지 않는다(차이 0.000006). 두 사안은 분리해 다룬다.


**✅ 채택 방어 조항 (필수 3종):**

| # | 조항 | 내용 | 실행 가능성 |
|---|---|---|---|
| 1 | **위치 단독 AUC를 핵심 관찰값으로** | 위치는 템플릿·태그와 무관하므로 **라벨 누수가 구조적으로 없는 유일한 지표**다. §4.2의 3신호 병기와 해석 규율을 그대로 적용한다 | ✅ 즉시 가능 |
| 2 | **템플릿 홀드아웃** | 일부 템플릿을 제외하고 기준을 세운 뒤, 보지 않은 템플릿에서 평가. 신호가 진짜면 새 템플릿에서도 작동해야 한다 | ✅ 가능 (아래 표) |
| 3 | **분해능·누수 명시** | 희귀도의 실질 분해능이 약 4이고 템플릿이 태그와 1:1 대응한다는 사실을 결과 보고와 논문 한계에 **먼저** 기재한다 | ✅ 서술 |

**템플릿 홀드아웃 여력 (실측):** 어느 템플릿을 빼도 양성 표본이 충분히 남는다.

| 제외 템플릿 | 남는 양성 라인 | 비율 |
|---|---|---|
| t8 (PBS_CON) | 9,501 | 64.1% |
| t7 (MPT) | 10,244 | 69.1% |
| t1 (CPU) | 12,114 | 81.7% |
| t2 (SCSI) | 12,634 | 85.3% |
| t9 · t4 | 14,791 · 14,811 | 99.8% · 99.9% |

**단, 한계 명시:** 상위 4종이 99.8%를 차지하므로 t9·t4를 빼는 홀드아웃은 사실상 무의미하고, 상위 4종 중 하나를 빼는 방식만 실질적이다. 즉 **홀드아웃 조합은 실질적으로 4가지**이며 이 역시 결과에 명시한다.

## 부록 A. 용어 정리

> AUC·ROC·효과크기 관련 용어는 **검정력 분석 §0.4 용어 대응표** 참조.

| 용어 | 뜻 |
|---|---|
| **alert 태그** | 로그 줄 맨 앞의 이상 표시 자리를 통칭. `-`(정상), `SCSI`·`CPU`·`PBS_CON` 등(이상). 위치와 무관, 제작자가 붙임. |
| **양성 / 음성** | 양성=원인 줄(하드케이스, `n_pos`), 음성=평범한 줄(비교군, `n_neg`). |
| **버스트 / 관측 단위** | 같은 로그가 짧은 시간에 몰린 덩어리. = (노드,템플릿,5분)으로 묶은 표본 1개. **검정력 분석에서는 "관측 단위"로 표기.** |
| **`n_pos` / `n_neg` / `n_eval`** | 검정력 분석 표기. 각각 양성 수 / 음성 수 / 총 표본 수(`n_pos + n_neg`). |
| **양성 구성비** | `n_pos / n_eval`. 매칭 비율이 결정(1:1 → 50%, 1:4 → 20%). |
| **노드** | 컴퓨터 한 대 (Thunderbird는 수천 대). |
| **템플릿** | 로그 문구에서 변하는 부분을 `<*>`로 지운 뼈대 (Drain3). 정본 6종. |
| **본문 없음** | 로그 메시지(`message`) 칸이 비어 있는 줄. 시각·노드·태그는 있으나 읽을 문구가 없다. Drain3가 한 템플릿(t3)으로 묶음. §5에서 제외. |
| **순환** | 정답을 정하는 축과 맞추는 축이 겹치는 것(답을 문제에 적어놓음). 위치를 라벨에서 빼 차단. |
| **교란** | 진짜 원인이 아닌데 결과에 영향 주는 변수(시간·노드). 양쪽 맞춰 상쇄(교란 통제). |
| **선택 편향** | 표본 고르는 방식 때문에 결과가 왜곡되는 것. 매칭 실패분을 버리면 발생 → 제외 금지. |
| **의사복제** | 가짜로 표본이 많아 보이는 현상. 줄이 아니라 관측 단위로 세어 방지. |
| **순열검정** | 정답을 5,000번 섞어 "우연 점수"를 만들고, 진짜 점수가 그보다 극단적인지 양측으로 검정. |
| **p < 0.05** | 우연히 이 점수가 나올 확률이 5% 미만. |
| **seed** | 무작위로 섞는 순서를 정하는 번호. 고정하면 재현 가능. |
| **민감도 분석** | 조건(예: 매칭 실패분 포함/제외)을 바꿔도 결론이 같은지 확인. |
| **로버스트** | 튼튼함. 조건(1:1↔1:4)을 바꿔도 결과가 안 흔들림. |
