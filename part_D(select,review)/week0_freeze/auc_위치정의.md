## 1. AUC 공식

AUC의 정의는 **"원인 하나, 평범 하나를 뽑았을 때 원인이 더 높을 확률"**. 계산은 쌍을 다 세는 것:

$$\text{AUC} = \frac{\text{원인이 이긴 쌍의 수}}{n_{pos} \times n_{neg}}$$

우리 경우 양성 14,819 × 음성 14,939 = **2억 2,138만 쌍**을 다 비교한 값. (실제론 Mann-Whitney U로 정렬해서 빠르게 계산)

## 왜 음성이 균등분포이면 AUC가 무의미해지는가?

- 음성이 [0,1] 균등분포면, 양성 하나가 값 $x$일 때 그게 음성보다 클 확률은 **정확히 $x$**. (0.7이면 음성의 70%보다 크니까)
 시험 점수 == 시험 친 사람(같은 수, 100점과 100명)/ 나 == 양성 / 타인 == 음성
 예시를 시험점수로 바꾼다면, 100명의 인원, 최소 1~100까지의 점수가 소수점을 제외한 정수로만 골고루 퍼져있을때(균등분포)
 만약 내가 70점이면?(양성 표본을 랜덤으로 뽑았을때, 그 값이 70이면) ==> 나보다 점수가 낮은 사람은 70명. 즉 아무나 나를 제외하고 비교햇을때 시험점수가 낮을 확률을? 70%.
 이것은 균등분포이고, 항등함수가 되는 이유이다.


$$P(X_{pos} > X_{neg} \mid X_{pos}=x) = x$$

이걸 모든 양성에 대해 평균 내면:

$$\text{AUC} = E[X_{pos}] = \text{양성 위치의 평균}$$

**검증:**

| | 값 |
|---|---|
| 양성 평균 | 0.553919 |
| 실제 AUC | 0.553967 |
| **차이** | **0.000048** |

**일치. 유의미한 결과로 쓸수 없음**

## 다른 선택지? 가설③

# 가설③ :  위치도 파일 전체가 아닌, 같은 노드의 1시간 로그 안에서 원인 줄이 어디쯤인지로 재야한다.
* llm에게 로그 뭉치를 넣으면, lost-in-the-middle이 일어남. 실험 후반부(2단계=압축 단계)에 llm에 로그뭉치를 넣으면, 뭉치 안 가운데를 놓치는 현상이 일어날수 있음. 따라서 우리가 재야할 위치도 뭉치안에서의 위치여야 한다. 즉, 후반부에 llm에게 뭉치 단위로 넣을테니, 위치도 파일 전체가 아니라 그 뭉치안에서 재는것이 맞다. 따라서 로그를 뭉치로 잘라 그 안에서 원인 줄 위치를 재고 AUC 평가. (후반부와 논리 맞춤. 대비하는것이 아닌, 기준통일.)

③이 ①②를 둘 다 피하는 이유:
- 뭉치에 정상 줄이 섞여 있어(②와 달리 순수하지 않음) 같은 뭉치 안에서 원인·정상이 다른 위치를 가질 수 있다 → 비교 가능.
- 뭉치 내부 위치는 시각과 분리돼(①과 달리) 매칭해도 죽지 않는다.
- 단, 뭉치를 양성 기준으로 중심정렬하면 원인이 항상 0.5가 되어 순환이 생기므로, 시계 기준 고정 격자(정각 경계)로 자른다.

위치? : 같은 노드의 시계기준 1시간 로그 뭉치안에서 원인 줄이 앞,중간,뒤 어디쯤인지를 0~1로 잰 값.
같은 노드? : ^#\d+#$를 제외한, 한 기계의 로그뭉치.(Thunderbird는 수천대의 슈퍼컴퓨터 로그.각 기계마다 노드로 구분되어짐.)

* ①,② 와 차이점?
* ①은 범위가 8개월이여서, 위치 = 시각 (시기를 외운 것.) ②는 관측 단위가 순수(양성만 or 음성만)라 양성·음성이 각자 0~1을 똑같이 채워 두 분포가 같아짐(AUC 0.5). (①은 음성만 균등, ②는 양쪽 분포가 서로 동일 — 상황이 다름.) 모두 유의미한 auc평가를 기대할수 없음.
