## 가설
- **H₀:** 결합 신호(rarity + 위치)가 hard-case cause 라인을 non-cause와 구분하지 못한다 (AUC = 0.5).
- **H₁:** 결합 신호가 cause 라인에 더 높은 점수를 준다 (AUC > 0.5, one-sided).

## 채점 기준(라벨) vs 신호(feature) — 분리 원칙 (핵심)

> **순환(circularity) 방지의 핵심:** 라벨을 정하는 축과 신호로 맞추는 축이 겹치면 안 된다. 위치가 라벨에도 있고 신호에도 있으면 "위치로 정의한 걸 위치로 맞히는" 자기충족이 된다. 따라서 **라벨에서 위치를 뺀다.**

| 구분 | 사용 축 | 위치 포함? |
| --- | --- | --- |
| **채점 기준(정답 라벨)** | **alert 태그만** | ❌ 제외 |
| **정답을 맞추는 신호** | **희귀도(rarity) + 위치** | ✅ 포함 |

- **라벨은 alert 태그로만 판정** — 첫 필드가 `-`이면 정상, alert 태그(PBS_CON·MPT·CPU·SCSI 등)면 이상. 위치·시간과 무관. (데이터 검증: `is_anomaly`/`is_hardcase`가 `alert_tag`로 완전 결정되며 `position_ratio`는 라벨 규칙에 미포함.)
- **신호는 희귀도 + 위치** — 라벨이 위치와 독립하므로, 위치를 신호로 써도 순환이 아니다. 위치는 "라벨과 무관하게 정해진 정답을, 위치로 예측할 수 있는가"를 검정하는 독립 예측변수가 된다.
- **왜 이걸로 순환이 끊기나:** 이전 판은 양성 라벨에 "(b) 중앙 위치(0.25~0.75)"를 넣어 위치가 라벨+신호 양쪽에 있었음. **(b)를 삭제**해 위치를 라벨에서 제거하면 고리가 끊긴다. 신호 쪽 위치는 그대로 유지.

## 표본 단위 정의 (핵심 — 확정)
- **검정 단위 = (노드, 템플릿, 5분 시간창) 하나를 독립 표본 1개로 센다.** 같은 노드에서 같은 템플릿이 5분 안에 연달아 나오면 1개, 5분 이상 잠잠했다 재발하면 새로 1개. **다른 노드에서 난 것, 다른 템플릿은 항상 별개.**
- **템플릿을 키에 포함하는 이유:** rarity 신호가 템플릿 단위로 정의되므로, 단위마다 희귀도 값이 하나로 깨끗하게 결정되려면 템플릿을 키에 넣어야 한다. (노드, 5분)으로만 뭉치면 한 단위에 여러 템플릿이 섞여 희귀도 값이 애매해진다. 템플릿 포함은 표본을 줄이지 않고 오히려 더 잘게 쪼갠다.
- **명목 라인 14,939개는 사용하지 않는다(의사복제):** Drain3로 묶으면 **9종**, 상위 4종(PBS_CON·MPT·CPU·SCSI)이 **99.2%(14,813개)**. 라인으로 세면 "1개 사건의 복사"를 표본 수천 개로 착각.
- **버스트 수 = 6,722개 (B 재계산 완료).** (노드,템플릿,5분) 단위 실측치. ±1시간 매칭 성공 기준은 6,652개, 실패 70개는 2단계 폴백 대상. 측정보고서의 795(5분)·941(1분)은 **노드 구분 없는 전체 기준**임이 확인됨(795 < 고유 노드 3,085이므로 노드별 집계일 수 없음). 논리적 하한 3,085를 초과하여 정합.
- **독립성 근거:** 동일 템플릿이 **3,085개 노드 · 211개 날짜**에 분산 발생(고유 노드 상위 15개 합계도 38%뿐) → 서로 다른 물리 노드의 독립 사건.
- **rarity 유효표본 한계 명시:** 하드케이스 템플릿이 9종뿐이라 rarity는 양성쪽 값이 사실상 9개 한계. 따라서 **결합 신호(rarity + 위치)로 검정**한다(위치는 같은 템플릿이라도 버스트마다 값이 달라 per-instance 변동 실재). rarity 단독 AUC는 9종 한계를 명시해 보조로만 보고.
- **동일 시간창 다중 템플릿 주의(뻥튀기):** 같은 노드·같은 5분에 여러 템플릿 동시 발생 시 근본원인 1개가 독립 표본 여러 개로 셈됨. 킬스위치 단계에서는 감수하되, **Tier-2 CI 산출 시 노드/템플릿 클러스터 부트스트랩으로 보정**.
- **공간 상관 주의:** 랙 단위 동시 장애로 다수 노드 동시 로그 → 노드별로는 독립으로 세지나 근본원인 1개일 수 있음. 위와 동일하게 클러스터 부트스트랩으로 재방어.
- **제외:** CHK_DSK(13개, tbird-admin1 단일 노드 전용) → 명시적 제외.

## hard-case 정의 (양성 = positive, 확정)
- **양성 = alert 태그 기반 non-ERROR cause 라인.** Thunderbird에서 **14,939개**(VAPI 제외 시 14,909개). 원인 여부는 **alert 태그**로만 판정 — 위치와 완전히 무관.
- **⚠️ 위치를 양성 정의에서 제외(라벨 누수 방지).** 이전 판의 "(b) 중앙 위치(0.25~0.75) cause 라인" 조항 **삭제**. 측정보고서의 "59.2% 중간 집중"은 라벨 기준이 아니라 **관측 결과**이며, 위치 신호가 유효하리라는 **정황 근거**로만 사용.
- 이들을 (노드,템플릿,5분) 버스트로 묶은 것이 **양성 독립 표본**.

## 음성 정의 & 비교군 매칭 규칙 (v2 — 재추출 규칙 확정)

> **현행 비교군 파일은 부적합(무작위 균등 추출).** 검증 결과: position_ratio가 0~1 완벽 균등(분위수 정확히 0.25/0.50/0.75, line_id 등간격), 시간범위가 8개월 전 구간 통째, 노드 3,876개로 하드케이스 상위 노드와 불일치. → **아래 매칭 규칙으로 B가 재추출.**

### 매칭 규칙 (confounder를 맞추고 라벨은 반대로)
1. **각 양성 버스트 (노드 N, 템플릿 T, 시간창 W)마다 음성을 매칭 추출.**
2. **맞출 것(교란 통제):** **같은 노드 N**, **±1시간 이내**(양성 버스트 시각 기준). 위치·시간·노드 교란을 양쪽에서 상쇄.
3. **반대로 둘 것(라벨):** 음성은 **alert 태그가 `-`인 non-cause 라인**. (양성=원인, 음성=평범 — 라벨은 정반대.)
4. **건드리지 말 것:** **position은 매칭하지 않는다.** 위치는 측정 대상 신호이므로 양쪽을 억지로 같은 위치 분포로 맞추면 신호를 죽인다. 위치는 자연 상태로 두고 검정이 차이를 잡게 한다.
5. **세는 단위:** 양성과 동일하게 **(노드, 템플릿, 5분)**. 라인 단위 음성과 버스트 단위 양성을 섞지 않는다.
6. **비율:** 최소 **1:1**(주 검정), 로버스트니스로 **1:4** 병기. 극단적 불균형(1:14000) 방어.
7. **음성 내 ERROR 처리:** 현행 비교군에 ERROR 1,896개 혼입 확인. 매칭 음성은 **non-ERROR(INFO) non-cause로 한정**하거나, ERROR 포함 시 그 사유·개수를 명시. (기본: non-ERROR로 한정.)
8. **후보 선택 기준 = 무작위 추출, `seed = 42` 고정.** ±1시간 창 안에 후보가 다수(수십~수백) 잡히므로 그중 하나를 고르는 규칙이 필요. **"가장 가까운 것"은 채택하지 않는다** — 음성이 항상 양성 직전·직후 라인이 되어 같은 장애 사건에 오염될 수 있고(장애 시작 전후 로그는 이미 정상이 아닐 수 있음), 시간 간격 특성이 양성과 인위적으로 유사해져 대비가 흐려짐. 교란 통제는 이미 "같은 노드 + ±1시간" 창 자체가 보장하므로, 창 안에서는 무작위가 적절.
9. **재현성:** `seed_negative = 42` 고정, 추출된 음성 `line_id` 목록을 `negatives_matched.csv`로 저장. 상세는 아래 **재현성 규약** 참조.
10. **1:4 로버스트니스도 동일 기준(무작위 4개, 동일 seed 계열).** 1:1과 선택 방식이 다르면 두 결과의 차이가 "비율 탓인지 선택 방식 탓인지" 구분 불가하여 검산의 의미가 사라짐. 후보가 4개 미만이면 **있는 만큼만 사용하고 그 개수를 기록**(억지로 채우려 ±1시간 창을 넓히지 않는다).

### 매칭 시간 범위 & 실패 처리 (확정 — B 매칭 통계 근거)
> B가 14,939개 양성에 대해 범위별 매칭률을 실측(같은5분 96.9% / ±30분 99.4% / ±1시간 99.5% / ±6시간+ 100%). 이를 근거로 아래 확정.
- **매칭 시간 범위 = ±1시간.** 근거: 같은5분은 461개(3.1%) 손실이 크고 — 그 461개가 "같은 노드 ±5분 내 정상 로그가 없는 = 조용하다 갑자기 튄" 케이스라 **오히려 진짜 하드케이스일 개연성**이 높아 버리면 안 됨. ±6시간+는 ±1시간과 결과 동일(70개 차)인데 "같은 시간대" 교란 통제만 느슨해짐. **±1시간이 균형점(손실 70개=0.47%).**
- **매칭 실패 처리 = 제외 절대 금지, 2단계 폴백.** 실패분(±1시간 기준 약 70개)을 제외하면 selection bias(원인다운 표본을 라벨-상관 기준으로 걸러냄). 절차: **①±1시간 같은 노드 매칭 → ②실패 시 같은 노드 전체 기간으로 시간 제약만 완화(노드는 유지) → ③그래도 실패(같은 노드에 non-cause 0)면 제외 말고 민감도 분석에서 별도 집계·보고.**
- **노드명 오염(`#N#`) 31개 = 제외.** 실제 호스트가 아닌 플레이스홀더라 "같은 노드 매칭" 전제가 성립 안 함(기술적 제외, 라벨과 무관하므로 bias 아님). **"노드 식별 불가 31개 제외" 기록 남길 것.** 전체의 0.2%로 영향 미미.

### 레벨필터 ERROR를 음성으로 쓰지 않는 이유
그 경우 "숨은 원인 vs 뻔한 에러"를 묻게 되어 킬스위치 질문("원인 vs 평범한 라인")과 어긋남. VAPI(흔함, 낮은 rarity) vs 하드케이스(희귀, 높은 rarity)가 자동으로 갈려 AUC가 인위적으로 부풀려짐. 이 대비는 검정이 아니라 **서술적 근거**로만 사용.

### ⚠️ p-해킹 방지 (재추출 절차)
- **현재 무작위 비교군으로 AUC는 아직 미측정(깨끗함).** 매칭 규칙을 먼저 확정·커밋한 **뒤에** 음성을 재추출하고 AUC를 측정한다.
- 만약 이후 무작위본으로 값을 본 적이 생기면 그 수치는 폐기하고 기록에 남긴다("무작위본 값을 보고 매칭본으로 갈아타 유리한 걸 고르는" 행위 금지).

## 신호(feature) 정의 — 확정 (희귀도 + 위치)

- **rarity(희귀도) — 고정.** 템플릿이 전체 로그에서 얼마나 드문가. 무조건 사용.
- **위치(position) — 사용.** 라벨(alert 태그)과 독립하므로 순환 아님. 위치가 원인 라인을 예측하는지 검정.
- **결합 근거:** rarity 단독은 템플릿 9종 한계라 유효표본 부족. 위치는 버스트마다 per-instance 변동이 실재하여 결합 신호의 분산을 확보. 둘을 결합해 검정.
- **잔여 리스크(정직 명시):** 위치 신호는 "중간=원인" 가정이 데이터에 의존적이며, 원인이 컨텍스트 꼬리에 있는 롱테일 케이스는 약할 수 있음. rarity와 결합해 보완하되, 실측 AUC가 낮으면 NO-GO 대응의 신호 재설계(시간간격·버스트성 등)로 이행.

## 재현성 규약 (난수 사용처 일괄 확정)

> 킬스위치에서 난수를 쓰는 곳은 **두 군데**(음성 추출 / 순열검정). 둘 다 사전에 고정하지 않으면 "여러 번 돌려 유리한 값 고르기"가 가능해지므로 아래를 프리즈에 못박는다.

| 용도 | seed | 반복 | 산출물 저장 |
| --- | --- | --- | --- |
| 음성 매칭 추출 | `seed_negative = 42` | — | `negatives_matched.csv` (line_id 목록) |
| 순열검정 (AUC 유의성) | `seed_perm = 7` | **5,000회 고정** | `perm_null_dist.npy` (귀무분포) |

- **반복 횟수는 결과를 보고 늘리지 않는다.** 순열 5,000회로 고정. p값이 애매하다고 10,000회로 늘려 재시도하는 것은 optional stopping이며 금지.
- **seed는 데이터 접근 전 확정하여 본 문서와 함께 커밋.** 실행 후 seed를 바꿔 재추출·재검정하지 않는다.
- **인덱스 파일이 최종 증거.** seed만으로는 라이브러리 버전 변화 시 재현이 깨질 수 있으므로, 실제 추출된 음성 `line_id` 목록과 순열 귀무분포를 파일로 남긴다.
- **라이브러리 버전 핀:** `requirements.lock`에 numpy/pandas/scipy 버전을 고정하고 함께 커밋.
- **재실행 금지 원칙:** 음성 추출·순열검정 모두 **1회 실행**이 원칙. 코드 버그 등으로 재실행이 불가피하면 사유·시각·변경점을 감사 로그에 기록하고, 이전 결과도 폐기하지 않고 보존한다.

## 의사복제 방어 규약
- **CI는 템플릿-클러스터 부트스트랩으로 산출.** 재표집 단위를 라인이 아니라 **Drain3 템플릿(9종)**으로 묶어 재표집 → 9종 집중이 신뢰구간에 정직하게 반영. (라인 부트스트랩은 N을 14,939로 착각해 CI를 인위적으로 좁힘.)
- **신호별 유효 표본 주의:** rarity는 템플릿당 값이 거의 동일 → 양성쪽 유효 분산이 9종 한계. **위치는 버스트마다 값이 달라 per-instance 변동 실재.** 결합 신호로 검정, rarity-단독은 9종 한계 명시 후 보조로만.
- **집중도 상한:** 5분 버스트 기준 단일 템플릿이 양성 독립단위의 과반 초과 시 재검토(라인 기준 99.2% 집중은 부적격 근거).

## 임계값 근거 (요약)
- **표본 300** — ROC 검정력(Hanley-McNeil 1982)상 소수 클래스 ~30–37개가 하한이나, 의사복제 방어 위해 300으로 보수 설정. (노드,템플릿,5분) 하한 ≥3,085로 10배 이상 마진.
- **cause 40** — 검정력의 실제 결정요인(소수 클래스 수)에 안전계수. 단, **템플릿 단위(9)로는 미달**임을 명시 → (노드,템플릿,5분) 단위 사용이 전제.
- **AUC 0.65** — 관례(Hosmer-Lemeshow "poor" 인정). rank-biserial r = 2·AUC−1 = 0.30 = Cohen medium 하한으로 방어. **측정이 조건②에 유리한 정황:** 하드케이스 59.2% 중간 집중(위치신호 유리 정황) + 템플릿이 2억 줄 대비 극희귀(rarity 유리) + VAPI(322만·흔함)는 레벨필터가 이미 처리(역할분담 명확).
