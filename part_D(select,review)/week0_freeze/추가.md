프리즈 문서에 존재하는 방법1.

auc는 양성, 음성을 1대1로 비교했을때 양성 위치가 더 높을 확률.
AUC = 1.0 → 원인이 항상 이김 (원인 위치가 늘 더 큼) = 완벽 구별
AUC = 0.5 → 반반 (원인이 이길 때도 질 때도 반반) = 구별 못 함
AUC = 0.334 → 원인이 34%만 이김 = 원인이 오히려 더 작은 값(앞쪽)에 있다

원인 0.9  vs  정상 0.2  → 원인 승
원인 0.1  vs  정상 0.7  → 원인 패
원인 0.3  vs  정상 0.2  → 원인 승
...
이 값이 auc

높다/낮다는 그냥 위치값의 크기예요. 0.9면 창 뒤쪽, 0.1이면 창 앞쪽. "더 높을 확률"은 "원인이 더 뒤에 있을 확률"이랑 같은 말이고, 우리 결과는 반대로 원인이 앞에 있다는 거예요.


이 방법의 문제는 auc를 계산해봤을때, 만-휘트니 유 공식으로 구하면 0.5540 <— 킬스위치에서 경고했던 auc 0.5값
또한, 양성 음성 평균을 따져보았을때, 여기에서 양성 음성 평균은 양성인 줄들의 위치값을 다 더해서 양성 개수로 나눈것.
이렇게 구했을때, 음성 평균이 0.5 <— 균등분포 현상
양성 평균 과 auc가 근사하게 됨.

위치 폭 중앙값은 
매칭했을때 양성, 음성 위치가 얼마나 벌어지나
—> 거의 안벌어짐 —> 매칭하면 위치가 똑같아짐 —> auc가 0.5로 붕괴

Q 과연 신호 판정을 위치 단독으로 해도 괜찮을까?
희귀도, 결합, 위치 셋중에 유일하게 위치만 누수가 없음.
진짜 신호가 있나를 판정하려면 위치밖에 못씀.

그래서 위치는 신호존재 여부를 판단,
희귀도는 누수 판단,
결합은 실제 압축기가 쓸 성능이 어떤가

혹시 "위치도 아까 아티팩트(장애후 쏠림) 의심 있었잖아"가 걸리면 — 맞아요, 그건 별개 문제예요. 위치는 라벨 누수는 없지만 장애후 쏠림 아티팩트는 있을 수 있어서, 그건 매칭으로 걷어내야 해요. 누수(템플릿)랑 아티팩트(쏠림)는 다른 문제고, 각각 다른 방법으로 처리해요.

다만 희귀도만 보고 GO 판정은 안 해요. 희귀도가 템플릿(=라벨)을 따라가서, 그것만 보면 신호가 좋은 건지 정답 훔쳐본 건지 구분이 안 되거든요. 그래서 누수 없는 위치 단독으로 검증하는 거예요.없애는 게 아니라 판정 기준에서 격리하는 거예요.

1 판정용
② 희귀도 단독 AUC → 참고용 (누수 확인)
희귀도는 템플릿에서 나와서 정답을 훔쳐봐요. 그래서 이건 높게 나와도 "신호가 좋다"고 못 믿어요. 근데 왜 재냐면 — "희귀도가 얼마나 누수됐나"를 드러내려고요. "봐라, 희귀도만 보면 0.99 나오는데 이건 라벨 훔쳐본 거다"를 보여주는 거예요. 투명성용이에요.
희귀도는 무조건 정답지가 될수 밖에 없음

③ 결합 AUC → 실제 성능 (최종 보고)
희귀도+위치를 합친 거요. 압축기가 실제로 쓸 신호는 이거예요. 근데 결합엔 희귀도가 섞여 있으니, 이게 좋아도 "위치 덕인지 희귀도(누수) 덕인지" 알아야 해요. 그걸 위치 단독(①)이랑 비교해서 판단하고요.
