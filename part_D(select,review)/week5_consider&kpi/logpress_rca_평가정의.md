# LogPress — 2층(Tier-2) RCA 평가기준 정리 (Root Cause Analysis)

> 출처: 최종_기획서 §8, RoleD_액션플랜 §1·§4·§7, 통합확정본 5단계(M6).
> 새로 만든 기준이 아니라 **이미 확정된 판정식을 한 곳에 모은 것**이다.
> 핵심: 2층은 "향상 증명"이 아니라 **"보존↔성능 관계의 최초 측정"**이다.

---

## 0. 한 줄 정의

**같은 압축률에서 압축 방식만 바꿔(LogPress vs baseline) 뒷단 모델에 RCA를 시키고,
정답률의 차이(Δ)만 본다.** 절대 정답률이 아니라 delta다.

$$\Delta = \mathrm{acc}(\text{LogPress}) - \mathrm{acc}(\text{baseline})$$

> **⚠ 흔한 오해 — RCA는 채점 프로그램이 아니라 '태스크(하는 일)'다.**
> RCA(Root Cause Analysis, 근본 원인 분석)는 "이 로그의 장애 근본 원인이 뭐냐"를 알아내는
> **작업 자체**다. "우리 압축기를 넣으면 점수가 나오는 공식 RCA 프로그램" 같은 건 없다.
> 실제 파이프라인은:
> `로그(context) → [LogPress 압축] → [LLM이 RCA 수행] → 원인 답변 → [정답 라벨과 대조 채점]`
> — **RCA를 수행하는 주체는 LLM**이고, **채점은 우리가 코드로**(모델 답 == Nezha 원인 라벨) 한다.
> 자동 채점 블랙박스가 아니라 우리가 파이프라인+채점을 돌리되, 정답 기준은 Nezha 라벨에 묶여
> 자의적이지 않다. K지선다는 별개 문제가 아니라 **RCA를 측정하는 방식 자체**다(§3·§7).

---

## 1. 왜 delta인가 (절대값이 아니라 차이)

- RCA는 원본 로그에서도 프런티어 모델 완전 정답률이 3.9~12.5%로 바닥이다.
  → **절대 정답률로는 우열이 안 갈린다.**
- 우리가 묻는 것은 "RCA를 잘하나"가 아니라 **"우리 압축을 쓰면 baseline보다 더 잘 맞히나"**뿐이다.
- 그래서 **압축 방식만 교체**하고 나머지(모델·압축률·질문·인시던트 집합)는 전부 고정한다.
  차이의 원인을 압축 방식 하나로 귀속시키기 위해서다.

---

## 2. 실험 세팅 (무엇을 고정하고 무엇만 바꾸나)

| 항목 | 설정 | 이유 |
|---|---|---|
| 바꾸는 것 | **압축 방식만** (LogPress ↔ baseline 4종) | delta의 원인을 압축 하나로 귀속 |
| 고정: 압축률 | 동일 compression_ratio | 같은 조건에서 비교 |
| 고정: 모델 | Llama-3.1-8B 주력 / Qwen2.5-7B 2차 | 백본 교란 제거 + 일반화 확인 |
| 고정: 인시던트 집합 | 같은 집합에 두 방법 적용 = **짝진(paired) 설계** | McNemar·paired bootstrap 성립 |
| 압축 대상 | **context만 압축, question은 미압축** | 질문까지 압축하면 태스크가 바뀜 |
| 데이터 | **Nezha** (원인 라벨 있는 유일 데이터) | Thunderbird는 이상 라벨이라 RCA 직접 검증 불가 |
| baseline | Random · StreamingLLM · H2O · PyramidKV | kvpress 재현 |

## 3. 태스크 형식 & 정확도 지표 (floor 회피)

자유서술 RCA는 작은 오픈 모델에서 정답률이 바닥이라 delta 측정 자체가 불가능하다.
그래서 **제약형(constrained)**으로 정답률을 잰다.

| 형식 | 정의 | 정확도 지표 |
|---|---|---|
| **K지선다** | 원인 후보 K개 중 택1 (K = 4~5 권장) | 정답 선택 비율 |
| **라인 지목** | 원인 라인 top-1 지목 | top-1 accuracy |

- 각 방법의 개별 정확도 보고는 **Wilson 신뢰구간**.
- 제약형으로 floor를 띄우는 것이 1차 방어. 그래도 바닥이면 §5 백업 발동.

## 4. PASS 판정식 (3중, 사전 확정)

아래 **셋을 모두** 충족해야 Tier-2 PASS.

| # | 조건 | 무엇을 보장하나 |
|---|---|---|
| ① | **Δ > 0** | 방향 — LogPress가 baseline보다 높다 |
| ② | **paired bootstrap 95% CI 하한 > 0** | 크기·안정성 — 차이가 0을 넘어 실재 (BCa, 10,000회) |
| ③ | **McNemar p < 0.05** | 짝진 유의성 — 우연이 아님 |

- **왜 McNemar인가:** LogPress는 재학습 없이(training-free) 단일 테스트셋에서 한 번 평가하므로,
  Dietterich(1998)에 따라 이 조건에서 허용 가능한 type I error를 갖는 검정은 McNemar다.
  (difference-of-two-proportions·resampled paired t-test는 금지.)
- 불일치쌍(b+c) < 25면 McNemar `exact=True`(이항검정)로 전환.

### 핵심 코드 (판정 3중)

```python
# ① 짝진 유의성: McNemar
b = np.sum((acc_log==1) & (acc_base==0))   # LogPress만 정답
c = np.sum((acc_log==0) & (acc_base==1))   # baseline만 정답
res = mcnemar([[np.sum((acc_log==1)&(acc_base==1)), b],
               [c, np.sum((acc_log==0)&(acc_base==0))]], exact=(b+c < 25))

# ② delta의 부트스트랩 95% CI (짝진 차이)
diff = acc_log - acc_base
ci = bootstrap((diff,), np.mean, confidence_level=0.95,
               n_resamples=10000, method='BCa', random_state=0)

# ③ 각 방법 정확도의 Wilson CI (개별 보고용)
lo_l, hi_l = proportion_confint(acc_log.sum(), len(acc_log), method='wilson')
```

## 5. FLOOR 백업 3단 (delta가 안 잡힐 때)

| 단계 | 대응 | 트리거 |
|---|---|---|
| 1차 | 제약형 태스크(K지선다)로 Llama 바닥효과 회피 | 기본 설계 |
| 2차 | 추론 특화 **DeepSeek-R1-Distill-Qwen-7B**로 교체 | 1차에서도 모든 방법 ≈ 0 |
| 3차 | Tier-2를 **"방향성 관찰"로 강등**, **Tier-1(보존율)을 핵심 성과로 프레이밍** | 2차에서도 delta 측정 불가 |

> 보존율(1층)은 모델 정확도와 **독립적으로** 측정되므로 바닥효과에 강건하다.
> 이것이 1층을 안전망(발표 가능 최소선)이라 부르는 이유다.

---

## 6. 이 지표가 "보존 ≠ 활용"과 연결되는 지점 (가장 중요)

- **1층 지표 = 보존율:** 원인 줄 KV가 압축 후에도 살아있나 (keep_mask 생존, 이진).
- **2층 지표 = 정답률(accuracy):** 그 살아남은 것으로 모델이 실제로 원인을 **맞혔나**.

두 지표가 다르기 때문에 **1층에서 이겨도 2층이 안 오를 수 있다.**
원인 줄을 보존해도(1층 통과) 모델이 그걸 활용해 답을 맞히진 못할 수 있기 때문이다(2층 미상승).

- delta가 **오르면** → "보존이 성능으로 이어진다"(보존→활용) 입증.
- delta가 **안 오르면** → 실패가 아니라 **발견**: "정보 보존이 병목이 아니라 **모델 능력이 병목**".

즉 2층은 향상 증명이 목적이 아니라 **보존과 성능 사이 인과 공백을 처음으로 측정**하는 것이다.

## 7. 선행 연구는 어떻게 쟀나 · 우리 방식의 위치

"공식 채점 프로그램에 넣으면 점수"가 아니라, 남들도 **벤치마크(문제셋 + 정답 + 채점규칙)**를
만들어 "정답 원인을 맞혔는지"를 잰다. 우리 K지선다는 그 흐름의 **간이·객관식 변형**이다.

### 7.1 대표 사례 — OpenRCA (Microsoft, ICLR'25)

- **무엇:** 실패 케이스 335개 + 텔레메트리 약 68GB(로그·메트릭·트레이스). 장애 케이스와
  텔레메트리를 주면 **LLM이 근본 원인을 식별**하는 태스크. (RCA를 하나의 "태스크"로 도입.)
- **채점:** "정답 원인 **요소**를 맞혔는지"를 본다. 7개 하위 태스크로 나뉘며 일부는 원인 요소
  하나, 일부는 둘을 식별하게 한다. 자유서술을 사람이 읽고 주는 점수가 아니라 정답 대조.
- **성능(우리 기획서의 3.9~12.5%가 이 숫자):** 멀티에이전트(RCA-agent)를 써도 정확도 약 11.3%.
  → **원본 로그로도 바닥이 낮다.** 우리가 절대값이 아니라 delta를 보는 이유(§1)와 직결.
- **볼 곳:** `github.com/microsoft/OpenRCA` · OpenReview `M4qNIzQYpd`.

### 7.2 다른 결의 측정

| 벤치마크 | 태스크·입력 | 주 지표 |
|---|---|---|
| **OpenRCA** (ICLR'25) | 텔레메트리 → 원인 요소 식별 | 정답 원인 식별 정확도(accuracy) |
| **TN-AutoRCA** (2025, 통신망) | 지식그래프 → JSON으로 원인·장비·해결책 반환 | **F1-Score**(다중 라벨) |
| **OpenRCA 2.0** (2026) | 원인 + **인과 경로**까지 | **Path Reachability · Node F1 · Edge F1** (과정 단위) |

### 7.3 최근 흐름 (판단에 반영할 것)

- **"원인 하나 맞히기" → "인과 경로·추론까지"로 기준이 올라가는 중.** OpenRCA 2.0은 최종
  라벨만 채점하던 방식을 넘어, 원인까지 이어지는 **인과 전파 경로를 채점**한다. 실제로
  "원인 서비스를 하나라도 맞히기"는 76%까지 오르지만, 그걸 검증된 인과 경로에 근거지우는 건
  61.5%뿐 — **맞혀도 근거 없는 진단(ungrounded)**이 약 1/5 존재함을 드러냈다.
- **벤치마크 점수 ≠ 실전 RCA.** RCA의 진짜 어려움(인과·규모·시스템 구조)은 벤치마크가 재는
  범위 바깥에 있다는 비판(Traversal, 2026)이 있다. 점수가 올라도 production-ready로 오인 말 것.

### 7.4 우리 K지선다의 정확한 위치 (정직한 자기평가)

- **정당성:** OpenRCA도 결국 "정답 원인을 맞혔는지"를 채점하므로 **흐름은 같다.** 우리는
  Nezha 원인 라벨을 **객관식으로 포장**할 뿐(정답을 지어내지 않음 — 오답 보기만 구성).
- **트레이드오프(한계로 명시):** 자유식별을 객관식으로 좁히면 **floor는 피하지만 태스크가
  실제 RCA보다 쉬워진다.** 즉 "측정 가능성"을 얻는 대신 "난이도"를 낮춘다. 최근 흐름이
  오히려 난이도를 **올리는**(경로·추론) 방향이므로, 우리는 반대로 가는 셈이다.
- **방어 문장:** "우리는 원인 **식별의 축소판(제약형)**을 재며, 목적은 절대 성능이 아니라
  **압축 방식 간 차이(delta) 검출**이다. 자유서술·인과 경로 평가는 본 범위 밖(future work)."

## 8. 한계 · 신뢰도 주의 (한계 섹션에 먼저 쓸 것)

- **Nezha 원인 라벨은 구문/코드영역 단위** → "라인 지목" 정확도를 재려면 **구문→줄 매핑**이
  선행돼야 한다(관문 M-N). **이 매핑 정합성이 곧 2층 정답률의 신뢰도**다. 매핑이 흔들리면
  delta도 흔들린다.
- **Nezha는 소규모·저부하(low-QPS)** 벤치마크 → 고동시성 장애를 완전히 대표하지 않는다.
- **train/dev/test는 인시던트 단위 분할**(라인 단위는 누수). context 압축만, question 미압축.
- **FastKV TSP layer(예: 15)는 Llama-3.1-8B(32층) 기준** → Qwen/DeepSeek는 재탐색 필요.

---

## 9. 한 문단 요약

Tier-2는 같은 압축률·같은 인시던트에서 **압축 방식만 교체**해 제약형 RCA(K지선다 / 라인 지목)
정답률의 **delta**를 재고, **Δ>0 · paired bootstrap 95% CI 하한>0 · McNemar p<0.05** 세 조건을
모두 충족하면 PASS한다. 데이터는 원인 라벨이 있는 **Nezha**뿐이고, 모델은 Llama-3.1-8B 주력에
Qwen2.5-7B로 일반화를 본다. floor면 제약형→DeepSeek→Tier-1 프레이밍 3단으로 물러난다.
RCA는 채점기가 아니라 **LLM이 수행하는 태스크**이며, 남들도 OpenRCA처럼 "정답 원인을 맞혔는지"를
벤치마크로 잰다 — 우리 K지선다는 그 **간이·객관식 변형**(floor 회피 대신 난이도 하향의 트레이드오프)이다.
2층 지표는 보존율이 아니라 **정답률**이므로, 1층을 이겨도 2층이 안 오를 수 있으며 —
그 경우는 실패가 아니라 "정보 보존이 아니라 모델 능력이 병목"이라는 **발견**이다.
