## 0. 실험 분류 — "재보고 / 반재실행 / 재실행"

새 run이 필요한지로 먼저 가른다. 대부분의 A는 **Tier-1 한 번 돌린 결과를 다르게 잘라 보는 것**이라 품이 거의 안 든다. 실제 재실행은 **B 3개**뿐 → 여기에 집중.

| 실험 | 종류 | 실제로 필요한 것 |
|---|---|---|
| A1 원인 보존율 | 재보고 | Tier-1 그 자체 |
| A2 압축률 곡선·cliff | 재보고 | Tier-1 M5 곡선(이미 산출물) |
| A3 최악 케이스 | 재보고 | 같은 run에서 min 보존율만 추가 |
| A4 놓친 원인 프로파일 | 재보고 | 버려진 줄의 레벨·위치·길이 집계 |
| A5 안정성 | 반재실행 | 같은 로그 여러 seed/모델 반복 |
| B1 모델 교체 | 재실행 | 백본만 교체 재돌림 |
| B2 위치 이동 | 재실행 | 원인 줄 위치만 조작 |
| B3 데이터 교체 | 재실행 | 다른 데이터셋 |

→ A1~A4는 새 판정식이 거의 필요 없음. Tier-1 판정식 아래 **보고 항목만 추가**. 구체화 품은 B에 몰아준다.

## 1. v7 Gate 선후 관계 (순서·선행조건)

B1·B2는 **어텐션 압축기(C v7) 전용** 스트레스라, v7의 Alert detectability Gate가 **GO**여야 의미가 있다. 게이트 전에 돌리면 "죽은 방법을 스트레스"하는 셈.

```
[v7: 어텐션이 Alert 줄을 잡나?]  ── NO-GO ──▶  어텐션안 폐기 · B1/B2 불필요
        │ GO
        ▼
[압축기 완성: S_j 라인 점수]
        │
        ▼
[Tier-1 보존율] ─▶ A1·A2·A3·A4 (재보고, 게이트 무관·상시 가능)
        │
        ├─▶ A5 안정성 (반재실행)
        │
        ▼
[스트레스: B1 모델 · B2 위치]  ← v7 GO가 선행조건
        │
        ▼
[B3 데이터 교체]  ← 데이터 확보가 선행조건(Nezha/BGL/HDFS), Q2 일반화와 연결
```

| 실험 | 선행조건 | 임계경로 | 시점 |
|---|---|---|---|
| A1~A4 | Tier-1 결과 | 밖(재보고) | Tier-1 완주 즉시 |
| A5 | Tier-1 파이프라인 | 밖 | 여유 구간 |
| B1·B2 | **v7 GO** | 밖(게이트 후) | v7 판정 후 |
| B3 | 데이터 추가 확보 | 밖 | Q2 일반화 |

> 압축기는 교체 가능(어텐션·위치·대안). **B1은 어텐션안 전용** — 위치·템플릿 압축기는 모델을 안 타서 B1 대상 아님.

## 2. 공통 뼈대 (모든 실험 5칸)

각 실험은 이 5칸으로 명세한다.

1. **조작 / 통제** — 뭘 바꾸고(딱 하나), 뭘 고정하나
2. **측정** — 지표. 기존 틀(보존율·K지선다) 재활용
3. **사전 판정식** — 방향 + 숫자 선. 결과 전 동결
4. **해석** — 양성/음성/애매가 각각 무슨 뜻
5. **우선순위 / 의존성** — 선행조건·시점

## 3. A · 다각도 (재보고 중심)

Tier-1 판정식(hard subset에서 4 baseline 대비 BH 보정 후 p_bh < 0.05, 방향 일관 b>c)은 그대로. 아래는 **그 위에 얹는 보고 항목**.

### A1 · 원인 보존율 (기본)
- 조작/통제: 없음(Tier-1 그 자체)
- 측정: `preservation_rate(rule='any')` — 원인 줄 토큰 하나라도 살면 보존
- 판정식: Tier-1 PASS 판정식 그대로
- 해석: 압축기의 기본 성능선
- 의존성: Tier-1

### A2 · 압축률 곡선 · cliff
- 조작: 압축률 50→60→70→80→90% 스윕
- 측정: 압축률별 보존율 곡선, **급락 지점(cliff)** 위치
- 판정식(보고형): "보존율이 `[TBD: 예 -X%p 급락]` 되는 압축률"을 안전 상한으로 보고. ▶ *뽑는 법: pilot 곡선에서 2차 차분이 가장 큰 지점 = cliff 후보, 사전에 급락 기준 %p 동결*
- 해석: "단일 숫자"가 아니라 "어디까지 압축해도 안전한가"
- 의존성: Tier-1 M5 곡선(이미 산출)

### A3 · 최악 케이스
- 조작: 없음(같은 run 재집계)
- 측정: 케이스별 보존율의 **min**(평균 아님)
- 판정식(보고형): `min 보존율 ≥ [TBD]`. ▶ *뽑는 법: 운영상 "이 밑이면 재앙"인 하한을 팀이 사전 합의*
- 해석: 평균 95%여도 핵심 장애서 0%면 재앙 → 운영 관점
- 의존성: Tier-1

### A4 · 놓친 원인 프로파일
- 조작: 없음(버려진 원인 줄만 필터)
- 측정: 버려진 원인 줄의 공통 특징 — 레벨(INFO/WARN/ERROR)·위치(앞/중간/뒤)·길이 분포
- 판정식(보고형): 판정보다 **실패 분석**. "놓친 원인 중 비-ERROR 비율", "중간위치 비율" 집계
- 해석: 자화자찬 대신 약점 정확히 파악 → 신호 재설계 근거
- 의존성: Tier-1

### A5 · 안정성
- 조작: 같은 로그를 여러 seed / 여러 모델로 반복
- 측정: 반복 간 보존율 **분산 / 일치율**
- 판정식: `반복 간 보존율 표준편차 ≤ [TBD]` 또는 `보존/미보존 방향 일치율 ≥ [TBD]`. ▶ *뽑는 법: pilot에서 3~5회 반복해 분산 관측 후 동결*
- 해석: 재현 가능한가(믿을 만한가)
- 의존성: Tier-1 파이프라인, 여유 구간

## 4. B · 스트레스 (재실행 · 여기에 집중)

### B1 · 모델 교체 — "LLM 의존" 저격
- **조작/통제**: 어텐션 추출 백본만 **Qwen ↔ Llama** 교체. 압축률·데이터·평가는 전부 고정
- **측정**: 같은 로그셋 원인 보존율(줄 단위)
- **사전 판정식**:
  `|보존율_Qwen − 보존율_Llama| ≤ [TBD]%p` **AND** `보존/미보존 방향 일치율 ≥ [TBD]`
  → 만족 시 **모델-불변(강점)**, 벗어나면 **모델 의존(약점)**
  ▶ *뽑는 법: 두 모델로 pilot 서브셋 돌려 보존율 차이의 자연 분산을 관측 → "이 정도면 같다"의 상한을 그 분산 기준으로 동결(예: 관측 분산의 2배 이내 등)*
- **해석**: 불변이면 "LLM 안 타는 튼튼한 방법", 다르면 어텐션안의 치명 약점 입증
- **의존성**: v7 GO 선행. 어텐션안 전용(위치/템플릿 압축기는 대상 아님). 액션플랜 "두 백본 재현"을 정식 실험으로 승격

### B2 · 원인 위치 이동 — "위치 편향" 저격 (v7 S_j 편향과 직결)
- **조작/통제**: **원인 줄만** 앞/중간/뒤로 이동. 나머지 줄·인과 흐름은 유지("깨끗한 버전")
- **측정**: 위치대(앞/중간/뒤)별 보존율
- **사전 판정식**:
  `앞→뒤 이동 시 보존율 하락폭 ≤ [TBD]%p` → **위치-강건**, 그 이상 급락 → **"원인이 아니라 위치를 보고 있음"(약점)**
  ▶ *뽑는 법: pilot에서 위치만 바꾼 소수 케이스로 하락폭 분포 관측 후 상한 동결*
- **해석**: 이 숫자를 미리 못 박으면 C 어텐션 게이트 평가 때 그대로 무기
- **주의**: 로그 전체를 섞으면 "위치 편향 vs 인과 붕괴" 구분 불가 → **원인 줄 위치만** 조작 필수
- **의존성**: v7 GO 선행

### B3 · 데이터 교체 — "데이터 의존" 저격
- **조작/통제**: 시스템 다른 데이터(Thunderbird / Nezha / +BGL·HDFS). 그리고 **한 데이터 튜닝 → 다른 데이터 테스트**(과적합 폭로)
- **측정**: 데이터셋별 원인 보존율, 튜닝셋 vs 테스트셋 격차
- **사전 판정식(단계형)**:
  - **현 단계** = **방향 확인(정성적)까지만** — 데이터 부족(Nezha 실데이터 2케이스)
  - **통계적 일반화 판정** = `n_incident ≥ [TBD]` 확보 후 (검정력 분석으로 뽑음, 킬스위치 300개 근거와 동일 방식)
  ▶ *뽑는 법: 킬스위치 때처럼 `NormalIndPower`로 필요 n 산출 후 동결*
- **해석**: 다 통하면 "일반적", 특정 데이터만이면 "요행", 튜닝셋만 잘 되면 "과적합"
- **의존성**: 데이터 추가 확보 선행. 로드맵 Q2 일반화 검증과 연결

### (추가 후보)
- **B4 노이즈 추가**: 무관 로그 잔뜩 섞어도 원인 잡나 → 판정식 `노이즈 주입 후 보존율 하락 ≤ [TBD]%p`
- **B5 극단 압축**: 90%+ 세게 압축해도 버티나 → A2 곡선의 cliff 지점과 연결

## 5. 평가 틀 재활용 (중요)

위 실험 **전부 새 평가 틀이 필요 없다.** 재는 건 항상 "원인 줄이 살았나(1층) / LLM이 맞히나(2층)". **압축기만 갈아끼우고 기존 보존율·K지선다·McNemar를 그대로 돌린다.** = 비교 대상만 늘리는 것(ablation에 조합 추가).

```
어텐션 압축기(C v7) ┐
위치 압축기          ├─▶ [살릴 줄 목록] ─▶ 같은 평가(1층+2층+스트레스) ─▶ 비교
대안(보너스)         ┘
```
