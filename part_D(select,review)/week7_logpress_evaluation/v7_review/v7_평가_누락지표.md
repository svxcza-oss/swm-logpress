# LogPress Phase 1 v7 — 평가(§7–9) 누락 지표 정리

v7 설계서의 평가 파트(§7 Target Score · §8 Ranking · §9 통계)에서 **빠졌거나 값이 확정되지 않은 지표**만 추린 목록. 킬스위치 프리즈 / 판정식프리즈 부속서 / 검정력 분석의 사전등록 기준과 대조함.

---

## A. 결과 보기 전에 반드시 고정해야 하는 지표 (최우선)

### 1. Paired 설계 검정력 / 필요 pair 수
- 예상 Delta를 power 0.8에서 잡는 데 필요한 matched pair 수.
- 기존 검정력 분석(n_pos ≥ 60)은 **AUC용(Hanley-McNeil)**이라 paired permutation 설계에 적용 불가.
- 없으면 NO-GO가 "신호 없음"인지 "표본 부족"인지 구분 불가.

### 2. Delta 최소 실용 효과크기 (임계값)
- GO를 가르는 Delta 하한.
- 킬스위치의 `AUC 0.65 = Cohen medium(r=0.30)`처럼 **효과크기 앵커로 근거**를 붙여 사전 고정.
- 현재 "pilot 뒤 고정" 원칙만 있고 숫자 없음.

### 3. Ranking 주지표
- Hit@1 / Hit@3 / percentile / MRR / rank-difference 중 **어느 것이 Primary인지 미지정**.
- "사전 고정한다"는 문장만 있고 실제 지정이 빠짐 → family 다중비교 위험.

### 4. 순열검정 사양
- 반복수 B, seed, 검정 방향(양측/단측).
- 킬스위치는 **B=5,000 · 양측 · seed 고정**으로 이미 확정 → 그대로 상속 가능.
- v7엔 사양이 없음.

---

## B. 검정 방법 사양 (중간 우선)

### 5. Bootstrap 사양
- BCa 여부 · 재표집 단위(**= pair**) · 판정규칙 "95% CI 하한 > 0".
- v7은 pair 복원추출만 언급, 나머지 미명시.

### 6. 다중비교 보정
- 검정 family 크기(Natural + Same-node × 여러 지표)와 보정 방식(BH / BY 등).
- §6.4는 head/layer **exploratory에만** BH를 언급 → confirmatory family 보정 규칙 부재.

---

## C. 주장 방어용 비교 지표 (필수 보강)

### 7. 템플릿 누수 통제 지표
- 템플릿 이질성/희귀도를 통제한 Delta, 또는 템플릿 홀드아웃 성능.
- 킬스위치 §13-1(템플릿 ≈ alert 태그 ≈ 라벨, 템플릿-단독 AUC ≈ 1.0)의 **attention 판** 방어가 없음.

### 8. 싼 baseline 대비 지표
- rarity + position 결합점수 대비 attention 우위.
- §11.1 Gate-후 baseline이 Random · Recent · Token→Line만 두고, **넘어야 할 기준선(싼 점수)** 비교가 confirmatory에 없음.
