# LogPress v7 · 평가 부분(7~11번) 쉬운 말 요약

> Role D 정리 노트 — 어려운 원문을 쉽게 다시 쓴 버전.
> 핵심 한 줄: **Alert 줄이 뒤 5줄한테 얼마나 참조받나 → 짝 Normal보다 높고, 창 안에서 상위인가 → 짝 구조 살려서 통계 낸다.**

---

## 7번 — Target 점수 S

- 매칭을 통해 Alert와 Normal을 짝지어 비교 (코드 레벨).
- Target 직후 **+1~+5 다섯 줄**이 Target을 참조한 정도(R)를 **평균** 낸 게 그 줄의 점수 S.
- 평균 범위는 위치가 어디든 **항상 이 5개로 고정**.
- 성공 조건: **S_Alert > S_Normal** (짝마다 Delta = S_Alert − S_Normal).

**정보 손실 방어**
- 평균 하나로 누르면 "모양"이 사라짐 → 5개 값의 분포가 어땠는지 안 보임.
- 그래서 보조(Secondary)로 **max · top-3 평균 · 원본 5개 값(profile)** 을 **함께** 저장.
- 단, **결과를 본 뒤 보조지표를 대표값으로 바꾸지 않음** (p-hacking 방지). 대표값은 끝까지 평균.

| | 5개 값 | Mean(주) | Max | Top-3 |
|---|---|---|---|---|
| 패턴 A | 0.03, 0.03, **0.45**, 0.03, 0.03 | 0.114 | 0.45 | 0.17 |
| 패턴 B | 0.11, 0.11, 0.12, 0.11, 0.12 | 0.114 | 0.12 | 0.117 |

→ 평균은 같아도 max/top-3로 "한 줄 집중 vs 골고루"가 갈린다.

---

## 8번 — Window 내부 Ranking

- 7번은 **짝 Normal 딱 1줄**과의 비교. 매칭은 그 1줄만 통제한 것.
- 그런데 Window는 21줄. **나머지 줄들은 통제 안 됨** → 그중 Normal이 Alert보다 높을 수 있음.
- 그래서 8번은 Alert가 **창 안에서 몇 등인지**를 확인. 7번의 착시를 잡는 역할.

**등수 구하는 법**
- 후보 줄 j 각각에 **Target과 똑같은 공식** 적용:
  `Q_j = mean(R(j+1,j) ... R(j+5,j))`
- 후보 범위는 **j = 5~15 (11개)**. ← 16~20은 뒤 +5줄이 없어 계산 조건이 달라져서 제외.
- 11개 Q값을 정렬 → Alert의 순위(rank/percentile) 확인.
- 정렬 결과가 Alert를 가리키면 = **창 안에서도 Alert를 제일 중요하게 본다는 근거.**
- 짝 Normal 창에서도 같은 위치 p의 등수를 구해 `rank 차이 = Normal rank − Alert rank` (양수면 좋음).

> **7·8번은 상호 보완**: 7번(짝 비교)이 놓치는 "실전 순위"를 8번이 잡아준다.

---

## 9번 — 통계 (짝 구조를 살린다)

각 짝의 Delta를 단위로 다룬다. 짝을 섞어 뭉치면 매칭이 버려짐.

- **순열검정 (부호 뒤집기)**: 각 짝 Delta 부호를 무작위 반전 → "방향이 무의미하다면?"을 재현 → 실제 값이 우연 분포 끝자락이면 유의.
- **부트스트랩 CI (복원추출)**: **짝을 통째로** 복원추출 → 평균 Delta 분포 → 95% 구간. 하한 > 0이면 안정적 양의 효과.
- **concordance (방향 세기)**: **Alert가 이긴 짝이 몇 개인가**의 비율. 크기 무시, 방향 일관성만. (평균이 이상치에 휘둘리는 걸 보완.)
- **AUC = 부가(Secondary)**: 이유 → **짝 정보를 안 쓰기 때문.** 전체 분포만 비교하니 매칭이 버려져서 조연.

**확인 순서**: ① Natural Delta 양수? → ② 순열검정/CI 지지? → ③ 8번 ranking 같은 방향?
**small-N**: 짝 적으면 p값 하나로 GO/NO-GO 안 정함. 효과크기·CI·concordance·rank·위치안정성 종합.

## 10번 — Natural vs Same-node

**다른 node 로그를 끼우냐 빼냐**의 차이 (둘 다 시간순은 유지).

- **Natural (Primary)**: 원본 그대로. 다른 node 줄이 자연스럽게 섞인 실전 환경.
- **Same-node (대조군)**: Target과 같은 node 줄만. 다른 node는 다 뺌.

**목적(핵심)**: 딱 "node 포함/배제"만 바꿔 비교 → **node locality가 신호를 강화하나 약화하나**를 봄.
→ "Same-node only가 맞는지 설계자가 미리 안 정하고, **데이터가 정하게 한다.**"

**부작용**: Same-node는 창 채울 후보 줄이 줄어듦. node에 로그 부족하면 그 짝은 Same-node에서 **탈락** (아래 보강 ③).
※ 짝(표본) 수 자체는 두 arm 동일 — 검정력은 안 줄어듦. 탈락으로 생기는 결측만 주의.

---

## 11번 — GO / BOUNDARY / NO-GO 판정

앞의 7·8·9 결과를 모아 최종 신호등을 켬.

- **GO**: Delta 양의 방향 + 순열/CI 지지 + ranking 개선 + 위치 바꿔도 방향 안 뒤집힘.
- **BOUNDARY**: 방향은 양수지만 CI 넓거나 효과 작음 / Same-node만 강함 / ranking 일부만 지지 → 표본·robustness 보강.
- **NO-GO**: Delta 0 근처·음수, 반복 안 됨, ranking 랜덤 → **멈추고 가정 재검토. Field/KV로 안 넘어감.**

**꼭 챙길 2가지**
1. **threshold(최소 효과크기)를 결과 보기 전에 고정.** 확증 데이터 본 뒤 안 움직임. (= 판정식 프리즈, Week 0 동결.)
2. **GO여도 주장 범위는 "Alert 줄을 포착할 수 있다"까지.** RCA·Field 중요도·KV 효율은 아직 별도 질문. Alert 라벨 ≠ 근본원인 정답.

## 보강 코멘트 3개 (설계 부정 아님 · 착시 방어용 sanity check)

**① raw mass 스케일 편향**
- R을 재정규화 없이 raw로 두면, **줄끼리 주고받은 어텐션 총량이 창마다 다를 수 있음** (시험지 만점이 창마다 다른 셈).
- Alert 창들과 Normal 창들의 총 mass가 체계적으로 다르면 Delta가 "신호"인지 "눈금 차이"인지 구분 안 됨.
- → **arm별 총 mass가 Alert/Normal 간 균형인지** sanity check.

**② 후보 5~15 제한 편향**
- 제한 자체는 정당(공평한 +5 확보). 하지만 **중요한 Normal 줄이 16~20에 몰려 있으면** 강한 경쟁자가 통째로 빠져 Alert 순위가 인위적으로 좋아 보일 수 있음.
- → 후보 제한이 결과에 주는 영향을 **Secondary로 점검**.

**③ Same-node 결측 짝**
- node 로그 부족하면 그 짝은 Same-node 창을 못 만들어 **탈락** → Natural과 **짝 집합이 달라져** 비교가 흔들림.
- → **양쪽(Natural·Same-node) 다 성립한 짝으로만** 비교. 탈락 짝 수는 따로 기록.
