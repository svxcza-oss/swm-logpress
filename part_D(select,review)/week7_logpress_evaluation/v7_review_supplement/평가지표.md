## A그룹 — 결과 보기 전 반드시 확정 (최우선)

### 1. 필요한 pair 수 (검정력)

**간단 설명:**
컴퓨터로 가짜 데이터를 만들어서 미리 연습해보는 것.
"Alert가 Normal보다 이만큼 높을 것 같다"를 가정하고 가짜 짝을 N개 만들어 검정을 돌린다.
이걸 여러 번 반복해서 "N개일 때 신호를 잡는 확률"을 구하고, N을 키워가며
**그 확률이 80%를 넘는 최소 N**을 찾는다. 그 N이 본 실험에 필요한 짝 개수.

- 80%는 관례. 10번중 2번은 실수할수 있다는것을 가정하고 들어간다.
- Cohen, J. (1992). "A Power Primer." Psychological Bulletin, 112(1), 155–159.(출처)
- 검정력 0.80만 다루며 이건 "일반적 사용을 위해 제안된 관례(convention)"라고 명시

- 넣을 값: 2번 파일럿에서 나온 평균 `d̄`, 표준편차 `s`
- 검정력 목표: 0.80
- 쓸 검정: 실제로 쓸 것과 동일 (paired permutation)
- **필요 pair 수 N = [채울 곳]** ← 파일럿 후 시뮬로 계산

### 2. Delta 최소 임계값 (합격선)

**간단 설명:**
파일럿 = 맛보기 실험. 전체 말고 짝 10~20개만 먼저 돌려서
"Delta 값이 대충 얼마나 흩어지나(표준편차)"만 잰다.
이 파일럿은 **눈금 재는 용도**이지 성공 증거가 아니다.

계산 순서:
1. 파일럿 짝마다 `Delta = S_Alert − S_Normal` 구하기
2. 그 값들의 평균 `d̄` = **[채울 곳]**, 표준편차 `s` = **[채울 곳]**
3. **임계값 = 0.5 × s = [채울 곳]**
   (0.5인 이유: Delta는 평균차라 Cohen's **d** 척도라서 medium=0.5.
    킬스위치의 0.3은 상관계수 r 척도라 다른 것.)

- 파일럿 짝 수: **[채울 곳, 10~20]**
- 파일럿 짝은 본 실험과 겹치지 않게 빼둔다 (연습문제로 시험 보면 반칙)

### 3. Ranking 주지표  ✅

- 주지표: **rank-difference = (Normal 등수) − (Alert 등수)**, 양수면 Alert가 더 상위
  (짝 구조를 그대로 쓰므로 Primary와 결이 맞음)
- Hit@1 / Hit@3 / percentile / MRR 은 전부 **Secondary**로 강등
- percentile 정의: **후보 5~15줄 중에서의 순위** (창 전체 21줄 중 순위가 아님)


- Hit@1 — alert가 딱 1등이면 성공(1), 아니면 실패(0). 여러 짝 모으면 → "몇 %가 1등이었나"

- Hit@3 — "3등 안에 들었냐?" alert가 상위 3등 안이면 성공. "몇 %가 top-3 안에 들었나"

- percentile — "상위 몇 %냐?". 11개 중 몇 % 위인지. 연속적인 위치

- MRR — "등수의 역수 평균", Mean Reciprocal Rank. 등수를 1/등수로 바꿔서 평균 내는 거. + 상위권 빈도수 측정.

### 4. 순열검정 사양  ✅ (킬스위치에서 상속)

- 반복수 B = **5,000**
- 방향 = **양측**
- 유의수준 α = **0.05**
- seed = **42**

## B그룹 — 검정 방법 사양

+여기 조금더 보충.
### 5. Bootstrap 사양  ✅

- 같은 질문을 데이터를 조금씩 바꿔서 질문. 매번 새로운 짝을 뽑아 던진다.
- 방식 = **BCa**
- 재표집 단위 = **pair** (줄·토큰 아님)
- 판정 규칙 = **95% CI 하한 > 0 이면 지지**

### 6. 다중비교  ✅

- 방침: 보정을 하지 않는다. 대신 confirmatory 지표를 Natural arm(원본 타임라인) × rank-difference 1개로 
- 사전 고정하여 검정 family 크기를 1로 만든다 (→ 보정 불필요).
- 나머지 arm·지표(Same-node, Hit@K, percentile, MRR, AUC)는 전부 secondary로, GO/NO-GO 판정에 쓰지 않는다.
- 단, 이 주지표 1개는 데이터 보기 전에 확정하며 결과를 보고 바꾸지 않는다.

### 7. 템플릿 누수 통제

**왜 필요한가:** Thunderbird는 템플릿이 alert 라벨과 거의 1:1이라, "Alert라서"가 아니라
"그냥 드문 템플릿이라" 어텐션이 몰릴 수 있음 (킬스위치 §13-1의 어텐션 판).

- 방어 방법 (택1 이상):
  - matched Normal을 **템플릿 희귀도까지 맞춰** 뽑기
  - 일부 템플릿을 빼고(holdout) 기준 세운 뒤 **안 본 템플릿에서 Delta가 살아남는지** 확인
