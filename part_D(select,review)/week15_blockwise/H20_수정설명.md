# H2O 블록와이즈 수정 설명

> 파일: `H2O_blockwise.py` (원본 `H2O_eval.py` + `H2O.py`는 그대로, 별도 새 파일)
> H2O = Heavy-Hitter Oracle. "어텐션을 많이 받은 토큰(heavy-hitter)" + "최근 토큰"을 남기는 압축 방식.

---

## 0. 왜 바꿨나 (한 줄)

기존 H2O는 `attn_implementation="eager"`로 돌려서, heavy-hitter 점수를 세려고 **전체 어텐션 행렬(N×N)을 `H2OKVCache_LayerWise`에 통째로 넘긴다.** 입력이 길면 이 N×N이 터진다(OOM).
→ **heavy-hitter 점수(hh_score)를 "전체 한 번에"가 아니라 "query 블록으로 쪼개서" 계산**하되, **결과(선택되는 토큰)는 원본과 동일**하게 만든 것이 이번 수정이다.

---

## 1. 바꾼 곳 요약

| # | 위치 | 기존 (`H2O_eval.py` + `H2O.py`) | 변경 (`H2O_blockwise.py`) |
|---|---|---|---|
| ① | import | — | `math`, `repeat_kv`, `get_query_states` 추가 |
| ② | 클래스 | — | `block_size = 1024` 추가 |
| ③ | hh_score 계산 | `H2OKVCache_LayerWise`가 **전체 attentions** 받아 계산 | **`_hh_score_blockwise()` 블록와이즈로 계산** ★ |

## 2. 각 변경 상세

### ①②⑤ import / block_size / sdpa — ObservedAttention과 동일
```python
import math
from transformers.models.llama.modeling_llama import repeat_kv
from kvpress.utils import get_query_states
...
class TrackingH2OPress(ScorerPress):
    block_size = 1024
...
model = AutoModelForCausalLM.from_pretrained(name, attn_implementation="sdpa", dtype=torch.float16)
```

### ③ hh_score 블록와이즈 (`_hh_score_blockwise`)
```python
def _hh_score_blockwise(self, module, hidden_states, keys, kwargs):
    bsz, num_kv_heads, k_len, head_dim = keys.shape
    num_heads = module.config.num_attention_heads
    groups = num_heads // num_kv_heads

    cos, sin = kwargs["position_embeddings"]
    q = get_query_states(module, hidden_states, (cos, sin))   # RoPE 적용 Query
    k = repeat_kv(keys, groups)                               # GQA 복제
    N = q.shape[2]
    scale = 1.0 / math.sqrt(head_dim)

    acc = torch.zeros(bsz, num_heads, k_len, device=keys.device, dtype=torch.float32)
    k_pos = torch.arange(k_len, device=keys.device).view(1, 1, 1, -1)

    for s in range(0, N, self.block_size):                   # query 블록 루프
        e = min(s + self.block_size, N)
        qb = q[:, :, s:e, :]
        logits = torch.matmul(qb, k.transpose(2, 3)) * scale
        q_pos = torch.arange(s, e, device=keys.device).view(1, 1, -1, 1)
        logits = logits.masked_fill(k_pos > q_pos, float("-inf"))   # causal mask
        probs = torch.softmax(logits, dim=-1, dtype=torch.float32)
        acc += probs.sum(dim=2)                              # query축 합 누적
        del logits, probs

    # query-head 그룹을 '합(sum)' → [num_kv_heads, k_len]  (H2O는 평균이 아니라 '합')
    hh = acc.view(bsz, num_kv_heads, -1, k_len).sum(2).squeeze(0)
    return hh
```

### ④ 토큰 선택 규칙 (`compress` 안, 원본 H2O 규칙 복제)
```python
hh_size = n_kept // 2
recent_size = n_kept - hh_size

hh = self._hh_score_blockwise(module, hidden_states, keys, kwargs)   # [num_kv_heads, k_len]

# (1) heavy-hitter: 최근 영역 뺀 곳에서 점수 상위 hh_size개
select_hh = hh[:, : k_len - recent_size]
_, keep_topk = torch.topk(select_hh, hh_size, dim=-1)
keep_topk = keep_topk.sort().values

# (2) recent: 가장 최근 recent_size개는 무조건 유지
keep_recent = torch.arange(k_len - recent_size, k_len, device=hh.device).repeat(num_kv_heads, 1)

# (3) 둘을 합쳐 최종 생존 토큰
keep_idx = torch.cat([keep_topk, keep_recent], dim=-1)
```

## 2-1. 코드 — 발췌냐 직접 짰냐 + 줄별 역할

### (가) 발췌 / 표준 / 직접 작성 구분

| 부분 | 출처 | 구분 |
|---|---|---|
| Q·K 준비 (`get_query_states`, `repeat_kv`) | kvpress / transformers | 패턴 차용 |
| `Q·Kᵀ·scale` / `softmax` / causal mask | 표준 어텐션 공식 | 표준 |
| for 루프로 블록 돌며 누적·버림 | query chunking (Rabe & Staats 2021) | **직접 작성(조립)** |
| hh_score = 그룹·query '합' | 원본 H2O `_update_hh_score`의 `grouped_attn.sum(dim=(2,3))` | **원본과 동일하게 재현** |
| heavy-hitter + 최근 선택 규칙 | 원본 H2O `H2OKVCache_LayerWise.__call__` (= H2O 논문) | **원본 로직 복제** |

→ ObservedAttention과 똑같이, **블록 누적 뼈대만 직접 조립**이고, **점수 집계·선택 규칙은 원본 H2O 그대로.**

### (나) 덩어리별 역할
- **덩어리 1 — 준비:** Q(RoPE 적용)·K(GQA 복제)·숫자 꺼내기. *(ObservedAttention과 동일)*
- **덩어리 2 — 블록 루프:** query를 끊어서 각 key가 받은 어텐션을 누적(`acc`), 블록은 버림. *(ObservedAttention과 동일한 핵심)*
- **덩어리 3 — H2O 집계:** 누적값을 **헤드그룹별로 '합'**(평균 아님!) → hh_score. H2O는 "많이 받은 토큰"이 중요하므로 합을 씀.
- **덩어리 4 — 선택:** hh_score 상위 **heavy-hitter**(최근 영역 제외) + **최근 토큰**을 합쳐 최종 생존. H2O 논문의 핵심 아이디어.

> ObservedAttention과 차이: **덩어리 3에서 '평균' 대신 '합'**(H2O 설계), 그리고 **덩어리 4(선택 규칙)가 추가**로 있음.

## 3. 오픈소스 출처 (어디서 따왔나)

| 구성요소 | 출처 | 역할 |
|---|---|---|
| `get_query_states` | **kvpress** (`kvpress.utils`) | RoPE 적용한 Query 추출 |
| `repeat_kv` | **transformers** (`models.llama.modeling_llama`) | GQA 복제 |
| `Q·Kᵀ / √d` → `softmax` → causal | **표준 어텐션 공식** | 어텐션 기본식 |
| query를 블록으로 쪼개 누적 | **query chunking** — Rabe & Staats (2021), arXiv:2112.05682 | N×N을 안 만들고 같은 합 |
| hh_score (query·그룹 합) | **원본 H2O.py** `_update_hh_score` (팀 구현) | heavy-hitter 점수 정의 |
| heavy-hitter + 최근 선택 | **H2O 논문** — Zhang et al. (2023), arXiv:2306.14048 *"H2O: Heavy-Hitter Oracle"* (팀 `H2O.py`가 구현) | 어떤 토큰 남길지 규칙 |

> **직접 짠 부분은 "for 루프로 블록 돌며 hh_score를 누적"하는 조립 코드뿐.** 점수 정의와 선택 규칙은 **원본 H2O(팀 코드 + 논문)를 그대로** 따랐다.

---

## 4. 왜 결과가 원본 H2O와 같나 (근거)

원본 H2O의 hh_score는 **`grouped_attn.sum(dim=(2,3))`** — 전체 어텐션을 (그룹, query)축으로 합한 것.
- 우리 블록와이즈의 `acc`는 그 **query축 합을 블록으로 나눠 더한 것** → `acc` == 전체 query 합.
- 거기에 그룹 합(`view(...).sum(2)`)을 하면 → **원본 hh_score와 동일.**
- 선택 규칙(heavy-hitter topk + 최근 윈도우)은 **원본 H2O.py 코드를 그대로 복제** → 같은 hh_score면 같은 토큰 선택.
- → **최종 생존 토큰이 원본과 동일.** 차이는 "N×N을 메모리에 올리느냐"뿐.

---

## 5. 검증

- **[A] CPU 수학 검증** (`verify_blockwise.py`): H2O용 hh_score(그룹·query 합)도 블록와이즈 == 전체. 최대오차 ≈ 1e-14 (= 0). → 로직 통과.
- **[B] GPU 동일성 검증** (남은 게이트): 작은 입력에서 **원본 H2O(eager) 생존 토큰 vs 블록와이즈 생존 토큰**이 같은지 실제 모델로 확인.

---

## 6. 안 바꾼 것 (중요)

- 모델 로딩 나머지, 데이터 로딩, `evaluate_line_retention`(평가), 출력·검증 로직 — **전부 원본 그대로.**
- H2O의 **선택 규칙 자체(heavy-hitter + 최근)**는 바꾸지 않았다. 계산을 "블록으로" 옮겼을 뿐.

## 요약 (발표/멘토용 한 문장)

> "H2O의 heavy-hitter 점수(`grouped_attn.sum`)를, **전체 어텐션(N×N)을 메모리에 올리지 않고 query 블록으로 나눠 같은 합을 누적**하도록 다시 구현했습니다. heavy-hitter + 최근 토큰 선택 규칙은 원본 H2O 코드(논문: Zhang et al. 2023)를 그대로 복제했고, RoPE·GQA는 kvpress/transformers 함수를 썼으며, 원본과 결과가 같음을 검증했습니다. (query chunking, Rabe & Staats 2021)"
