## GPU 피크란?
- 추론 중 GPU 메모리 최고 사용량
- 하지만 피크 실측값엔 kv만이 아니라 모델 가중치, 활성화까지 다 섞인다.
- 그래서 순수 Kv절감은 이론 계산값으로만 보고 피크 실측은 실제로도 안터지고 줄더라 확인용으로 사용.


## 베이스라인 분류 — 무엇으로 KV를 남기나

| 베이스라인 | KV 선택 기준 (기반) | 어텐션 점수 읽나? | 동적/정적 | eager forward 필요? |
|---|---|---|---|---|
| **SnapKV** | 최근 쿼리의 어텐션 점수 → 중요한 prefix 토큰 top-k | ✅ 읽음 | 동적 | ✅ 필요 |
| **H2O** | 누적 어텐션 점수 높은 토큰(heavy hitter) + 최근 | ✅ 읽음 | 동적 | ✅ 필요 |
| **ObservedAttention** | 관측된 어텐션 가중치로 점수화 후 제거 | ✅ 읽음 | 동적 | ✅ 필요 |
| **StreamingLLM** | 맨 앞 sink 토큰 + 최근 윈도우 (**위치 고정**) | ❌ 안 읽음 | 정적 | ❌ 불필요 |
| random KV | 무작위 제거 | ❌ | 정적(무작위) | ❌ 불필요 |
| level filter (우리 비교군) | 로그 레벨(ERROR/WARN 등) | ❌ | 정적 | ❌ 불필요 |
| **우리 압축기** | 로그 신호(레벨·희귀도·위치) + 어텐션 | ✅ 읽음 | 동적 | ✅ 필요 |

### 두 부류로 갈림

- **어텐션 점수 기반 (동적):** SnapKV · H2O · ObservedAttention · 
  - 런타임에 어텐션 점수를 읽어 남길 KV를 고름 → 점수를 메모리에 띄우는 **eager 어텐션 필요**
- **위치·규칙 기반 (정적):** StreamingLLM · random KV · level filter
  - 고정 규칙으로 남김(위치·무작위·레벨) → 어텐션 점수 안 읽음 → **eager 어텐션 불필요**

## §4 forward 비용 처리 — 비교 상대별 방법

| 비교 상대 | 방법 |
|---|---|
| **점수 기반** (SnapKV · H2O · ObservedAttention) | forward가 양쪽 공통 → 소거 지름길 OK (또는 끝까지 실측해도 자동 상쇄) |
| **위치·규칙 기반** (StreamingLLM · random KV · level filter) | 소거 지름길 쓰지 말 것. 끝까지 **실측값 그대로** 사용 → 우리 eager forward 오버헤드가 그 숫자에 정직하게 잡히게 둠 |

> 원칙: "끝까지 실측하면 공통분은 저절로 상쇄된다."
> → 점수 기반끼리만 'forward 빼자' 지름길을 쓰고, 위치·규칙 기반에는 실측값을 그대로 둔다(빼주면 우리에게 유리하게 조작한 셈).

## §5 합격 기준 — 파레토 '같음' 판정 (오차율 처리)

**오차율은 숫자로 정하지 않는다.** "5% 이내면 같음" 같은 임의 기준 대신, 여러 번 재서 흔들림(신뢰구간)이 0을 걸치는지로 판정한다.

### 순서
1. **측정** — 차이값(우리 − baseline)을 표본으로 모은다. 예: `[+3, +1, +1, +2, +4, ...]` 
+ 네자 데이터셋을 기준으로 장애 케이스별 logpress/baseline을 비교한 차이값을 뽑아낸다. 베이스라인 별로 logpress와 비교하는데 38개 장애 케이스를 비교하면 CI 1개가 된다.
2. **계산** — 그 표본으로 **부트스트랩 95% 신뢰구간(CI)**을 뽑는다. 예: `[+1.2, +3.5]`
   - CI = 측정값 하나가 아니라 **측정값들로 계산한 "범위"**. 측정은 매번 흔들리니 "딱 3"이 아니라 "1.2~3.5 사이"로 폭을 준다.
3. **판정** — CI가 0을 기준으로 어디 있는지 본다.

| CI 위치 | 판정 |
|---|---|
| CI 전체 > 0 | **이김** |
| CI 전체 < 0 | **짐** |
| CI가 **0을 포함** | **같음** |

**파레토 합격:** 두 축(보존율·메모리) 모두 '짐'이 없고, 최소 한 축에서 '이김'.

### 표본이 뭔지 — 축마다 다름
- **보존율 축:** 표본 = **케이스들** (케이스마다 보존율 차이 → 그 묶음으로 CI)
- **메모리·속도 축:** 표본 = **반복 측정 횟수** (같은 조건 N번 재서 그 묶음으로 CI)
- ※ 베이스라인 5개는 표본이 아니라 **5번의 1:1 비교** → 각자 CI를 냄. 비교가 많아지므로 '이김' 선언엔 **BH-FDR 보정**(1층과 동일).

### 정할 숫자 세 개
| 숫자 | 뭐냐 | 값 |
|---|---|---|
| 케이스 수(네자 데이터셋 정제 필요) | 보존율 축 표본 | 20~30+ (많을수록 CI 좁아짐. 2개면 다 '같음'으로 빠짐) |
| 측정 반복 N | 메모리·속도 축 표본 | 속도 10회↑ / 메모리 3회 (워밍업 1~2회 제외) |
| 부트스트랩 B | CI 계산 내부 재표집 | 5,000 (코드 상수, 1층과 동일) |

> 핵심: 오차율을 사람이 정하지 않고 **데이터의 흔들림이 '같음'의 경계를 정한다.**
> 값들은 관례 수준이라 절대적이지 않음 — 중요한 건 **실험 전에 정해서 프리즈**(결과 보고 바꾸면 어뷰징).
> 1층에 이미 짠 부트스트랩 CI 함수를 메모리·속도 차이값에 그대로 재사용(추가 비용 ≈ 0).



## (측정)CI 뽑는 순서

**0. 입력**
- 차이값 배열 준비: 각 케이스에서 `우리 보존율 − baseline 보존율` → 길이 38 배열
diff = [+0.05, 0.00, −0.03, +0.02, ...] # 길이 38

- 재표집 예시
### 재표집 1회 = "같은 6칸을 복원추출로 다시 채움"
- 원본에서 **아무거나 하나 뽑고 도로 넣기**를 6번 → 6칸 채움
- 중복 뽑혀도 OK, 어떤 값은 안 뽑혀도 OK

resample #1 = [+0.05, +0.05, 0.00, +0.02, −0.01, +0.04]
↑ +0.05 두 번 뽑힘, −0.03은 이번엔 안 뽑힘
mean(#1) = (+0.05+0.05+0.00+0.02−0.01+0.04)/6 = +0.0250


### 재표집 2회 = 다시 뽑으면 다른 조합 → 다른 평균
resample #2 = [−0.03, 0.00, +0.02, +0.02, +0.04, +0.05]
mean(#2) = +0.0167


### 재표집 3회
resample #3 = [+0.04, +0.05, +0.02, 0.00, −0.03, +0.02]
mean(#3) = +0.0167

→ "이 데이터로 평균을 다시 뽑으면 대충 이런 값들이 나오더라"는 **평균의 분포**가 생김.
→ 이 5,000개를 정렬해 2.5%·97.5% 자르면 95% CI.

> 핵심: 원본 6칸(실제 38칸)을 **복원추출로 다시 채워 평균 1개** → 이걸 5,000번 = 평균 5,000개.
> 새 데이터를 더 재는 게 아니라, 있는 걸 섞어서 "평균이 얼마나 흔들리나"를 보는 것.


## "CI가 0을 기준으로" 가 무슨 뜻이냐

핵심: CI 안의 값은 전부 **차이값 = (우리 − baseline)** 이다.
→ 그래서 **0 = 차이 없음 = 같음** 이 기준점이 된다.

- 값이 **양수** = 우리가 baseline보다 **높다** (보존율↑ / 메모리 절감↑)
- 값이 **0** = 둘이 **같다**
- 값이 **음수** = 우리가 **낮다** (짐)

CI는 그 차이값이 들어갈 **범위**이므로, 0을 기준으로 세 경우:

[+1.2, +3.5] 범위가 통째로 0보다 큼 → 어떤 값이든 우리가 높음 → 이김
[−3.5, −1.2] 범위가 통째로 0보다 작음 → 어떤 값이든 우리가 낮음 → 짐
[−1.0, +2.0] 범위가 0을 걸침 → +일 수도 0일 수도 −일 수도 → 같음


마지막이 '같음'인 이유: 진짜 차이가 +2일 수도, 0일 수도, −1일 수도 있어서
**"우리가 확실히 다르다"고 말할 수 없음** → 사실상 같다고 본다.

> 요약: 차이값이 "우리 − baseline"이라 **0이 '같음' 지점**.
> CI(차이의 범위)가 0 위 / 0 아래 / 0 걸침 → 이김 / 짐 / 같음.
